# 配置目录规范

本目录继承根 AGENTS.md。所有说明和新增注释使用中文；现有程序字段、合同编号、枚举、环境变量名和版本摘要保持原标识，禁止机械汉化。

## 一、配置分层与权威

1. 项目行为由根规范规定；本目录存可审查的静态合同源码、算法参数及部署路径，不能作为额外业务数据库。
2. paths.yaml 负责机器来源与临时传输路径；project_workspace_storage_policy_v1.json 负责工作区和临时存储规则；workbench.yaml 保留遗留工作台连接配置语义。
3. 现役 V4 的运行来源、合同版本、参数绑定、Owner、Publication 和 Head 以 PostgreSQL 的精确版本为准。修改磁盘上的同名合同文件不等于修改已封存的数据库合同，也不得静默覆盖其摘要。
4. 历史合同、候选合同和现役合同必须按实际消费者区分；不得按文件名最新或修改时间选择生效版本。旧配置的删除或退休须有引用核对。

## 二、变更规则

- 配置服务于本地个人盘后研究，不为每个模块、来源修订或Release增加人工审批、合同层和门禁。普通研究与严格历史用途分开；真实晚采集数据不得伪装当时可知，也不得仅因不具PIT资格阻止普通研究。
- 来源分块、逐日行情新结构及跨版本共享先测实际问题与收益，不作为无条件配置项。优先处理已证实重复，不能为少建表将来源版本表扩成日线JSON库。

- 优先维护现有明确职责文件，不为每轮修复新增一套配置、合同和路径覆盖层。新增项说明消费者、字段类型、默认值、拒绝条件和版本影响。
- 因子、阈值、窗口和业务范围变更须有需求依据及独立验证；本轮规范整理不授权修改业务参数或批量重编码历史合同。
- 路径只在部署配置声明，不复制进入算法。通达信源只读；新临时与缓存仅 G 盘；不得通过配置另建源码工作区、数据库、Schema 或服务端口。
- 既有磁盘来源路径是当前采集/兼容接线，不能直接移动或删除后宣称已完成 PG-only。停止落地副本必须先适配消费者并验证来源流式留存。
- 读取配置不允许隐式写数据库、扫描导入、迁移和修复。不存在或不合法的关键配置明确报错，不能回退到桌面报告、旧目录或其他数据库。

## 三、安全、中文与检查

- 不读取或输出 .env 等密钥文件内容，不将连接密码、令牌和个人安全配置提交 Git。公开模板仅引用环境变量名。
- JSON/YAML 使用 UTF-8，说明使用中文；字段名及程序要求的状态常量保留兼容。新增说明字段须先确认消费者允许，不能给严格合同随意加字段。
- 修改后检查解析、键值兼容、源目录只读、G盘临时目录和相关消费者；已封存合同需核对摘要身份，不能只以 JSON 可解析作为业务通过。
- 本目录的历史字节归档继续受自身约束；不为统一文字修改冻结字节。当前业务开发暂停，本次仅授权规范及相关静态配置整理。
