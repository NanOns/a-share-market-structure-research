# BaoStock API 分析与系统接入方案 V1

- 文档版本：`BAOSTOCK_API_ANALYSIS_AND_INTEGRATION_PLAN_V1`
- 编制日期：2026-09-16
- 当前阶段：文档分析与接入设计，不启用生产访问
- 阶段结论：`DEGRADED_PASS`
- 适用系统：大 A 交易工作台 V3.3 / M14 在线增强
- 上游约束：`AGENTS.md`、`M14_SOURCE_VALIDATION_V1_0`、`P12_16_FALLBACK_AND_HISTORY_INTEGRATION_V1`

## 1. 结论摘要

BaoStock 可以作为系统后续的**主流在线历史数据来源**，优先承担盘后日线、换手率、交易日历、证券基础资料、行业、指数成分、财务数据和公司报告等补充任务。它不应替代现有通达信本地快照的主身份，也不应成为页面点击生成当日数据时的同步强依赖。

建议形成以下数据源分工：

1. 通达信本地数据继续作为当日行情与历史价格主身份，保持现有 V3.3 主流程不变；
2. BaoStock 作为盘后串行采集的主在线历史来源，先用于校验、补充及独立事实表；
3. 腾讯继续承担当前换手率主在线来源，搜狐、证券时报保留备用；
4. BaoStock 的 `turn` 经口径验证后，可升级为历史换手率主来源，并可在盘后成为当日换手率的重要候选来源；
5. BaoStock 失败、超时、额度不足或数据未更新时，只降级在线能力，绝不阻断本地研究包生成；
6. BaoStock 的复权方法与通达信可能不同，只能用于独立审计和交叉验证，不能覆盖冻结的本地复权身份。

在按“每只股票、整段日期一次查询”的前提下，约 6,200 只证券完成一次 170 交易日不复权日线回填，理论主体调用量约 6,200 次，而不是 `6,200 × 170` 次。日常单日全市场增量同样约为 6,200 次，因此用户提供的每日 50,000 次上限对核心日线任务是充足的。该估算必须由小范围真实试跑确认服务端分页、会话刷新、失败重试是否额外计次。

## 3. 接口能力归纳

### 3.1 会话

典型调用流程：

```python
import baostock as bs

login_result = bs.login()
# 串行执行查询并遍历结果集
bs.logout()
```

返回对象通常包含 `error_code`、`error_msg`、`fields`，结果通过 `next()` 和 `get_row_data()` 逐行读取。所有数值入库前都应做显式类型转换，不能把字符串返回值直接当数值使用。

### 3.2 历史行情

核心接口：`query_history_k_data_plus()`。

主要参数：

| 参数 | 含义 |
|---|---|
| `code` | `sh.600000`、`sz.000001` 等 BaoStock 代码 |
| `fields` | 逗号分隔的返回字段 |
| `start_date` / `end_date` | 查询日期范围 |
| `frequency` | `d`、`w`、`m`、`5`、`15`、`30`、`60` |
| `adjustflag` | `1` 后复权、`2` 前复权、`3` 不复权 |

日线常用字段包括：

`date, code, open, high, low, close, preclose, volume, amount, adjustflag, turn, tradestatus, pctChg, peTTM, pbMRQ, psTTM, pcfNcfTTM, isST`

这组字段与当前系统关联度很高：

- `open/high/low/close/preclose`：本地行情指纹复核；
- `volume/amount`：成交量、成交额交叉校验；
- `turn`：换手率候选事实；
- `tradestatus`：交易/停牌状态；
- `isST`：证券状态辅助事实；
- `peTTM/pbMRQ/psTTM/pcfNcfTTM`：后续基本面或估值研究输入，不应直接混入当前 V3.3 排序。

周线、月线可返回 OHLC、成交量、成交额、换手率和涨跌幅。分钟线通常只提供 OHLC、成交量、成交额等字段，且历史范围和指数支持能力需在试跑中单独验证。

### 3.3 基础资料与交易日历

| 接口 | 主要用途 | 建议接入角色 |
|---|---|---|
| `query_trade_dates()` | 交易日历 | 对本地交易日判定做外部校验 |
| `query_all_stock()` | 指定日期证券集合 | 生成 BaoStock 当日可查询代码集 |
| `query_stock_basic()` | 证券基础资料 | 名称、上市/退市等基础映射 |
| `query_stock_industry()` | 行业分类 | 独立行业事实，不覆盖现有板块身份 |

### 3.4 指数与成分股

主要能力包括上证 50、沪深 300、中证 500 成分查询，以及指数日/周/月行情。成分股数据具有时点属性，必须保存来源日期和接收时间，不能用当前成分回填历史日期。

### 3.5 财务、公司报告与分红

常见能力包括：

- 盈利能力：`query_profit_data()`；
- 营运能力：`query_operation_data()`；
- 成长能力：`query_growth_data()`；
- 偿债/资产负债：`query_balance_data()`；
- 现金流：`query_cash_flow_data()`；
- 杜邦分析：`query_dupont_data()`；
- 业绩快报、业绩预告；
- 分红送转、复权因子；
- 存贷款利率、准备金率、货币供应量等宏观数据。

财务数据必须按 `pubDate` 或等价公开日期做 as-of 控制。任何季度数据若缺少可证明的公开日期，均不得进入历史回放，以防未来数据泄漏。

## 4. 与现有系统的适配判断

| 数据能力 | 适配度 | 当前建议 |
|---|---:|---|
| 日线 OHLCV/成交额 | 高 | 盘后主在线校验与补充来源 |
| 170 日历史行情 | 高 | 使用单股整段日期查询，适合回填 |
| 换手率 `turn` | 高但需验口径 | 先进入独立事实层，不立即参与 Tier/排序 |
| 交易日历/证券资料 | 高 | 低频缓存，做代码与日期校验 |
| 行业/指数成分 | 中高 | 以时点合同独立存储 |
| 财务数据 | 中高 | 作为后续独立模块，严格 as-of |
| 实时行情 | 低 | 不作为页面点击链路的同步实时依赖 |
| 分钟线 | 中 | 暂不进入首期，避免额度和时效风险 |
| 前/后复权行情 | 仅审计 | 不改变通达信冻结复权口径 |

## 5. 换手率字段的关键问题

BaoStock 日线直接提供 `turn`，这比从成交量和流通股本自行推导更适合首期接入，但仍需关闭以下审计问题：

1. 数值单位是百分数还是比例值；
2. 分母是流通股本、自由流通股本还是来源自定义口径；
3. 除权、股本变更、停牌、上市首日及 ST 场景如何处理；
4. 当日值何时稳定，盘中查询与盘后查询是否一致；
5. 与腾讯、搜狐、证券时报同日同股的差异分布；
6. 与本地 `volume`、可获得股本数据的推导值是否具有稳定关系。

因此首期状态应为：

```text
source_id = BAOSTOCK
field = turn
denominator_basis = SOURCE_DEFINED_UNVERIFIED
ranking_eligible = false
display_eligible = true（仅在日期和行情指纹通过后）
```

完成至少 10 个交易日、覆盖正常股/ST/停牌/股本变化样本的口径验证后，才允许把 `ranking_eligible` 改为 `true`。这与当前搜狐、证券时报的 `DECLARED_ONLY` 管理原则一致。

## 6. 请求预算与串行设计

### 6.1 项目预算线

即使外部上限为 50,000 次，系统也不应运行到上限边缘：

| 阈值 | 行为 |
|---:|---|
| 0—39,999 | 正常串行执行 |
| 40,000 | 软告警，停止低优先级任务 |
| 45,000 | 项目硬停止，保留至少 5,000 次安全余量 |
| 50,000 | 外部绝对上限，系统不得触达 |

在官方计数规则未明确前，`login`、`logout`、每次查询、会话刷新和重试都按一次请求记账。服务端结果集逐行 `next()` 是否计为额外请求，必须在试跑中观察；不能事先假定免费。

### 6.2 调用量粗估

| 任务 | 估算调用量 | 说明 |
|---|---:|---|
| 登录、日历、证券集合、基础资料 | 小于 10 | 以实际计数器为准 |
| 全市场单日增量 | 约 6,200 | 每只证券一次日线查询 |
| 170 交易日全市场回填 | 约 6,200 | 每只证券一次整段日期查询 |
| 同时拉三种复权 | 约 18,600 | 首期不做，只拉不复权 |
| 六类财务接口、全市场、单季度 | 约 37,200 | 必须与核心日线错峰并分批 |

禁止采用“每个交易日、每只股票各发一次请求”的方式；170 日全市场会超过百万次，既浪费额度，也显著增加黑名单风险。

### 6.3 严格单连接执行器

建议新增唯一的 `BaoStockSerialWorker`：

```text
任务生产者 -> 持久化优先级队列 -> 单进程租约/文件锁
          -> 单线程 BaoStock 会话 -> 请求计数账本
          -> 规范化校验 -> 原子物化 -> capability receipt
```

必须同时具备：

- 全机器唯一租约，禁止两个托盘实例同时连接；
- 单进程、单线程、单活动会话；
- 不使用线程池、异步并发或多进程分片；
- 所有调用先占用预算，再发请求；
- 网络失败最多一次有界重试，重试也计数；
- 会话异常后先关闭旧会话，再串行重登；
- 达到项目硬停止线后立即落账并退出，不自动跨越预算；
- 调度任务可断点续跑，已成功的代码不重复请求。

## 7. 数据合同建议

建议建立 `BAOSTOCK_SOURCE_CONTRACT_V1`，至少冻结：

- 包名与精确版本、安装包 SHA256；
- 官网和文档版本观察时间；
- 允许的数据集、字段和频率；
- 单连接与每日预算策略；
- 代码映射版本；
- 日期、时区、单位、空值及停牌语义；
- 复权标志与禁止覆盖本地主身份的规则；
- 失败降级和熔断规则；
- 每个 capability 的准入状态。

| 数据集合同 | 内容 | 首期状态 |

## 8. 接入现有 V3.3 的链路

### 8.1 首期：独立旁路，不改变生产结果

```text
BaoStock 串行采集
  -> 独立 staging
  -> 日期/代码/单位/空值校验
  -> 与通达信 close、volume、amount 指纹绑定
  -> BAOSTOCK_DAILY_RAW_V1
  -> 审计报表
```

此阶段 V3.3 不读取 BaoStock 参与排序，目的是证明稳定性、日期语义、调用量和数据口径。

### 8.2 第二期：接入 170 日历史消费者

保持现有 `TODAY_RESEARCH_HISTORY_170_CONSUMER_V1` 的固定物化身份不变。BaoStock 只建立新的并行数据集：

- 缺口检测：检查本地 170 日物化是否缺日期或缺证券；
- 交叉校验：比较不复权收盘价、成交量、成交额；
- 补充事实：提供 `turn`、`tradestatus`、估值字段；
- 任何来源不一致都写审计对象，不静默覆盖本地值。

只有新的历史数据集完成全量验收后，才允许创建显式的新合同版本；不能原地改变旧 Parquet 或旧 manifest 的身份。

### 8.3 第三期：换手率接入

建议路由优先级分为盘中和盘后两套：

- 页面当日生成、尚未确认 BaoStock 当日更新：腾讯 -> 搜狐 -> 证券时报；
- 收盘后且 BaoStock 日期/指纹/口径均通过：BaoStock 可进入主源候选，再由审计结果决定是否高于腾讯；
- 历史回放：优先使用已物化且合同通过的 BaoStock 历史 `turn`，禁止回放时临时联网。

系统必须记录最终使用来源，不能把多来源值合并后丢失来源身份。

### 8.4 页面点击链路

页面“生成当日数据”只能读取最近一次已验收的 BaoStock 本地物化批次，不直接等待 BaoStock 网络请求。若当日批次尚未就绪：

1. 继续执行本地通达信主流程；
2. 按现有腾讯/搜狐/证券时报链路获取可用换手事实；
3. 在回执中标记 BaoStock capability 为 `STALE` 或 `UNAVAILABLE`；
4. 不阻塞页面，不把旧日 BaoStock 数据冒充当日数据。

## 9. 分阶段实施计划

### B0：文档与合同冻结

- 阶段合同：`BAOSTOCK_B0_DOCUMENT_AND_CONTRACT_V1`
- 本文即当前阶段产物；
- 验收：范围、预算、串行约束、身份和降级边界明确；
- 当前结果：`DEGRADED_PASS`，原因是尚未执行真实 API 与服务条款人工复核。

### B1：连接和字段小样本

- 固定 `baostock==0.9.3` 并记录包哈希；
- 单次登录，查询 5—10 只股票、5 个交易日；
- 验证错误码、日期、代码、单位、空值、停牌和 `turn`；
- 验证系统确实只有一个活动连接；
- 不改生产数据库，不参与排名。

### B2：换手率口径验证

- 选取至少 50 只股票，覆盖主板、创业板、科创板、北交所、ST、停牌、次新及股本变化样本；
- 连续观察至少 10 个交易日；
- 与腾讯、搜狐、证券时报及可推导值做差异分布；
- 明确单位、分母、稳定时间和异常规则；
- 通过后才关闭 `SOURCE_DEFINED_UNVERIFIED`。

### B3：170 日小范围物化

- 先选 50 只股票，单股一次拉取完整 170 日区间；
- 记录实际调用次数、耗时、断线、重登和返回行数；
- 只取 `adjustflag=3`；
- 与现有 170 日物化做日期和行情指纹对齐；
- 原子写入独立目录，禁止修改通达信根目录。

### B4：全市场 170 日回填

- 预计主体调用约 6,200 次；
- 按证券代码稳定排序，断点续跑；
- 每批完成即写 manifest 与哈希；
- 当日调用达到 40,000 即停止所有非核心任务；
- 验收后才能注册为历史可消费数据集。

### B5：每日盘后增量

- 等市场收盘且本地交易日确认后运行；
- 先探测少量锚点证券，确认 BaoStock 已更新到目标日；
- 未更新则延后，不循环高频探测；
- 全市场串行拉取后完成审计、物化和回执；
- 页面只消费完成态批次。

### B6：财务与指数扩展

- 财务任务按季度、数据集和证券切片；
- 与日线核心任务分开预算；
- 所有财务事实带公开日期，禁止未来函数；
- 指数成分按时点保存，不回填覆盖历史。

## 10. 验收标准

正式准入至少同时满足：

1. 官方使用条款、50,000 次限制、黑名单规则和并发限制完成人工复核并留证；
2. 连续试跑期间无并发连接，租约机制可证明；
3. 每日请求账本可重放、可审计，45,000 项目硬停止有效；
4. 目标日期、证券代码、字段单位、停牌和空值语义通过；
5. 与本地行情的日期及指纹差异有明确阈值和处置规则；
6. 170 日任务采用单股整段日期查询，实际调用量在预算内；
