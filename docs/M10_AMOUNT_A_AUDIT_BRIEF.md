## 1. 先给结论

M10 金额 A 目前属于“文档方向正确，但精确定义未封口；代码实现的是可解释的临时代理，不应继续当作最终板块金额 A”。

这不是简单的单方错误，核心冲突是统计对象不同：

| 项目 | 文档想表达的方向 | 当前实现实际表达的含义 | 审计判断 |
|---|---|---|---|
| 统计对象 | 板块成员金额，按板块层面与过去基准比较 | 每只成员股票自己的金额比，再对成员比值取中位数 | 不是同一个指标 |
| 时间基准 | 当前日相对前 20 个交易日的均额，排除当前日 | 个股当前成交额相对该股前 20 个交易日均额，排除当前日 | 时间方向一致，层级不同 |
| 当前字段 | `amount_vs_prior20` 被设计成 M10 的 A | `sector_cycle_daily.amount_vs_prior20` 实际是成员个股比值中位数 | 字段名掩盖了代理语义 |
| 是否能直接作为最终 M10 条件 | 可以，但还缺聚合、成员可比性和有效性细则 | 只能作为预览/诊断代理 | 需要综合定稿 |

因此本问题的准确表述是：

1. **文档不是完全错误**：它正确要求金额指标进入 M10 主线条件，使用排除当日的前 20 日基准，并且不覆盖旧的含当日金额比。
2. **文档也不是完全闭合**：没有把“板块成员金额”到底按板块金额总和、固定成员总和，还是成员个股比值统计说清楚。
3. **当前代码不是算术错误**：M8 个股 `amount_vs_prior20` 的公式实现与 M8A 合同一致，M9 再取成员中位数也有注释和可追溯依据。
4. **当前代码不能被称为文档所说的最终 M10 A**：它没有实现“板块金额总和 ÷ 板块过去 20 日金额均值”这一字面语义，而是实现了另一个指标。
5. **不能在没有定稿前直接把当前代理替换成另一条公式**：需要先由 Astra 审计并确定统计对象、成员时间口径、有效样本、缺失处理和版本迁移规则。

## 2. 被审计的文档要求

### 2.1 M7-M15 升级主文档的明确内容

`docs/WORKBENCH_M7_M15_IMPLEMENTATION_PLAN_V2_1.md` 已经给出了以下约束：

- M9 的 `member_amount_sum` 是“同板块纳入范围去重股票金额”；不能把不同板块金额直接相加作为市场总额；未知金额不能当作 0。
- M10 定义了三个主线维度：
  - `P`：当前 20 日同类强度百分位；
  - `B`：共同有效成员上涨宽度；
  - `A`：板块成员金额 / 前 20 日均额；
  - `R`：共同强势成员留存率。
- M10 的金额条件进入分类门槛：
  - `REACCELERATING`：成交额 / 20 日均额不低于 `1.2`；
  - `NEW`：成交额 / 20 日均额不低于 `1.1`；
  - `FADING`：成交额需要与其他指标共同严格走弱。
- `sector_cycle_daily` 要保存 `member_amount_sum`、`amount_valid_count` 和 `amount_vs_prior20`。
- 旧金额公式要保留，新金额/量比使用新字段；不同语义不能覆盖同一列。
- 金额原始值以元保存，显示层才转换为万、亿、万亿；NULL 必须显示为暂无/数据不足，不能转成 0。
- 固定样例要求：前 20 日金额均为 100，今日为 300 时，新 `amount_vs_prior20=3`；旧含当日均额公式仍单独得到 `300/110`，两者不能覆盖同列。

这些要求说明文档的总体方向是：**新增一个排除当前日的、可解释的金额比指标，并保留旧字段语义**。

### 2.2 详细升级文档的公式

`docs/WORKBENCH_M7_M15_DETAILED_UPGRADE_PLAN.md` 的 M8 成交额部分明确写出：

```text
amount_ratio_1_20 = 当日成交额 ÷ 前20个有效交易日平均成交额
amount_ratio_5_20 = 最近5日平均额 ÷ 再前20日平均额
```

并且说明基准窗口不包含当日。

这条公式对**个股金额因子**是清楚的，但没有继续说明 M10 的板块 A 如何从个股金额因子或板块日金额派生出来。因此，M8 的公式不能自动等同于 M10 的板块公式。

### 2.3 M8A 个股技术合同的明确内容

`docs/M8A_TECHNICAL_HISTORY_CONTRACT_V1.md` 明确规定：

```text
amount_ratio20      = 当日成交额 ÷ 包含当日的 20 日均额       （旧合同）
amount_vs_prior20   = 当日成交额 ÷ 前 20 日均额               （新合同）
```

其中：

- 当前日明确排除在分母之外；
- 前 20 个观察不足或分母非正时为 NULL；
- 不通过跳过缺失行来延长窗口；
- 每行保存合同版本、质量代码和口径 JSON。

这部分是已经明确且实现正确的**个股层公式**，不是 M10 板块 A 的完整定义。

### 2.4 M10 v2.2/v2.3 状态合同的缺口

`docs/M10_MAINLINE_STATE_CONTRACT_V2_2_PREVIEW.md` 和 `docs/M10_MAINLINE_STATE_CONTRACT_V2_3_PREVIEW.md` 都规定金额条件参与状态分类，并要求 `predicates`、缺失字段和冲突解释可追溯。

但是，M10 v2.3 合同没有完整写出以下关键内容：

- A 的分子是 `member_amount_sum`，还是成员个股金额比值的中位数/均值；
- A 的分母是板块日总金额的前 20 日均值，还是每只股票各自前 20 日均值；
- 板块成员新增、删除时，前后金额是否使用同一可比成员集合；
- `amount_valid_count` 是否只是描述字段，还是金额 A 的最低有效样本门槛；
- 一个交易日有部分金额缺失时，是 NULL、按已有成员求和，还是降级为代理；
- “前 20 个有效交易日”与“不能通过跳过缺失行延长窗口”发生歧义时应采用哪一种；
- `amount_change_3d` 是两个 A 值的差，还是最近 3 日金额窗口与此前窗口的重新计算比值；
- 旧 `amount_ratio20`、个股 `amount_vs_prior20`、板块 `amount_vs_prior20` 的字段命名和合同版本如何隔离。

因此，M10 文档目前是“方向和门槛已写，统计对象和数据质量细则未写完”。

## 3. 当前代码是如何实现的

### 3.1 M8：先计算每只股票的金额比

代码位置：`src/workbench_analysis/technical.py`。

当前个股计算等价于：

```text
r[i,t] = raw_amount[i,t]
        ÷ mean(raw_amount[i,t-20], ..., raw_amount[i,t-1])
```

实际代码使用：

```python
group["amount_ratio20"] = _safe_ratio(amount, group["amount_ma20"])
group["amount_vs_prior20"] = _safe_ratio(
    amount,
    amount.shift(1).rolling(20, min_periods=20).mean(),
)
```

所以 M8 产生两条不同语义的字段：

- `amount_ratio20`：保留旧合同，20 日均额包含当前日；
- `amount_vs_prior20`：新合同，分母是当前日前 20 个输入观察，当前日不包含在内。

这个实现与 M8A 合同和固定样例一致：前 20 日为 100、今日为 300 时，新字段为 3，旧字段为 `300/110`。

### 3.2 M9：同时生成板块原始金额，但 M10 A 没有使用它

代码位置：`src/workbench_analysis/sector_cycle.py`。

M9 先对当前板块/交易日的成员做去重后合并。当前板块原始金额的实现等价于：

```text
member_amount_sum[s,t]
  = Σ raw_amount[i,t]
    （i 属于板块 s 在 t 日的成员，且该金额为有限正数）
```

同时记录：

- `amount_valid_count`：当前板块当天正且有限的原始金额成员数；
- `total_member_count`：当前板块当天纳入范围成员总数；
- `member_amount_sum`：当天板块成员原始成交额总和。

但是，M10 使用的 `amount_vs_prior20` 并不是由 `member_amount_sum` 做时间序列滚动计算得到的。代码明确写成：

```python
amount_ratio_valid = (
    group.member_amount_vs_prior20.map(_finite)
    & group.member_amount_vs_prior20.gt(0)
)

"amount_vs_prior20": _median(
    group.loc[amount_ratio_valid, "member_amount_vs_prior20"]
),
```

其中 `group.member_amount_vs_prior20` 来自 M8 的每只成员股票 `amount_vs_prior20`。因此当前 M9/M10 的实际公式是：

```text
A_proxy[s,t]
  = median(
      { r[i,t] |
        i ∈ M[s,t],
        r[i,t] 为有限正数 }
    )
```

`window_stats` 还把该口径明确标记为：

```text
MEMBER_MEDIAN_STOCK_AMOUNT_VS_PRIOR20
```

这说明当前实现并非隐藏地误用了字段；它是一个有名字、有注释的临时代理。但这个名字只存在于窗口统计证据里，主字段仍叫 `amount_vs_prior20`，容易让使用者误以为它是板块总金额比。

### 3.3 M10：把该代理当作 A 参与主线分类

代码位置：`src/workbench_analysis/mainline.py` 和 `config/mainline-v2.3-preview.yaml`。

M10 当前读取：

```python
amounts = [_number(value) for value in cycle["amount_vs_prior20"]]
current_a = amounts[-1]
```

当前状态门槛为：

```text
NEW             : current_a >= 1.10
REACCELERATING  : current_a >= 1.20
FADING          : current_a 相对比较日严格下降，且其他衰退条件同时满足
```

代码的 3 日金额变化为：

```text
amount_change_3d = A_proxy[t] - A_proxy[t-3]
```

比较日由板块自身已观测日期序列的索引确定。当前代码没有重新计算“最近 3 日板块金额均值 / 更早 20 日板块金额均值”。

因此当前 M10 的真实语义是：

> “典型板块成员的当前成交额，相对各自前 20 日成交额基准的中位数，是否达到 1.10/1.20 或比 3 个观察位置前下降。”

这和文档字面上的：

> “板块成员金额总和，相对板块过去 20 日金额均值，是否达到 1.10/1.20。”

不是同一个问题。

## 4. 文档要求的理想实现应是什么

如果按 M10 文档中“板块成员金额 / 前 20 日均额”的字面含义实现，最直接的公式应是：

```text
S[s,t] = 板块 s 在交易日 t 的有效成员原始成交额之和

D[s,t] = mean(S[s,u])
         其中 u 为 t 之前的前 20 个基准交易日

A_doc[s,t] = S[s,t] / D[s,t]
```

为了让这条公式可以真正进入合同，还必须同时补齐以下定义：

1. `S[s,t]` 使用 t 日成员集合，还是使用固定的可比成员集合；
2. 成员金额缺失时，`S[s,t]` 是否仍可用已有成员求和；
3. `D[s,t]` 的 20 日窗口是连续的 20 个主交易日，还是允许跳过缺失日向更早日期扩展；
4. `S[s,t]` 和 `D[s,t]` 的最低成员数、最低覆盖率和金额有效率；
5. 板块成员变化时，金额变化是否允许同时反映“成员数量变化”；
6. 零金额、停牌、无成交和未知金额是否都是不同状态；
7. `A_doc` 的结果字段是否继续叫 `amount_vs_prior20`，还是改成可以直接表明“sector aggregate”的名称；
8. `amount_change_3d` 仍使用 `A[t]-A[t-3]`，还是定义独立的 3 日金额窗口指标。

## 5. 两种实现分别有什么缺陷

### 5.1 文档方案的缺陷：方向对，但缺少可执行的统计定义

文档方案的主要优点是符合“板块金额”的直觉，也与 M9 已保存的 `member_amount_sum` 相连。但在没有补定义前，它有以下缺陷：

#### 缺陷 A：板块成员集合变化会污染金额变化

如果昨日 2 只成员各成交 100，今日新增 1 只成员且 3 只都成交 100：

```text
昨日板块金额 = 200
今日板块金额 = 300
```

即使原有成员的交易活跃度完全没有变化，板块总额也会看起来增长 50%。这可能是“板块覆盖扩大”，不一定是资金在原有板块成员中扩张。

#### 缺陷 B：文档没有决定“总和”还是“典型成员”

“板块成员金额”通常会被理解为成员金额总和，但 M8 已经有逐股金额比。如果 M10 想使用逐股比值的中位数，文档必须明确写出“成员个股比值中位数”，不能继续写成板块成员金额总和。

#### 缺陷 C：有效样本规则不完整

文档要求未知金额不算 0，但还没有明确：当天只有 1 只有效金额成员、其余成员缺失时，是否允许产生一个看似正常的 A。也没有在 M10 结果中要求 `amount_ratio_valid_count` 或金额覆盖率。

#### 缺陷 D：“前20个有效交易日”与“不跳过缺失”存在解释冲突

“前20个有效交易日”可能被理解为忽略缺失日、向更早日期继续找满 20 天；而 M8A 的总则明确不允许用跳过缺失行的方式延长窗口。若不裁定，两个实现都可以声称自己符合文档。

#### 缺陷 E：3 日变化没有独立公式

文档描述了“较 3 日前变化”，但没有说明这是 A 值之差、百分比变化，还是重新计算的 3 日窗口比。三者会产生不同结果，不能只靠字段名猜测。

### 5.2 当前实现的缺陷：代理可解释，但不是文档字面上的最终 A

当前实现的主要优点是：

- 直接复用了已按 M8 合同验证过的个股金额比；
- 排除了当前日进入个股分母，避免了旧 `amount_ratio20` 的自包含偏差；
- 使用成员中位数，降低单只股票极端放量对板块指标的支配；
- 未知金额不会被填成 0；
- 代理口径在 `window_stats.amount_basis` 中有解释。

但它不能直接冒充文档中的板块金额 A，原因如下：

#### 缺陷 1：分子层级不同

文档要求的是板块金额总和；当前实现对每只股票先做归一化，再取中位数。一般情况下：

```text
median(stock_amount / stock_prior_mean)
≠ sector_amount_sum / sector_prior_mean
```

这不是取平均顺序的小误差，而是两个不同统计问题。

#### 缺陷 2：对成员规模变化不敏感，但也可能漏掉板块总量变化

如果新增成员数量使板块总成交额显著增加，而原有成员的个股金额比都接近 1，当前中位数仍接近 1；它不会把成员数量扩大解释为原有成员的资金扩张。这在某些分析目的下是优点，在“板块总金额扩张”这个文档目的下则是缺陷。

#### 缺陷 3：对集中式放量不敏感

例如 3 只股票的个股金额比为 `[4.0, 1.0, 1.0]`：

```text
当前代理 A_proxy = 1.0
```

如果该放量股票占板块成交额很大，板块总金额可能已经显著扩张，但中位数会把这种集中式变化压平。

#### 缺陷 4：有效数量没有完整进入 A 的质量门

当前 `amount_valid_count` 统计的是原始金额正值成员数；M10 A 实际需要的是有效的个股 `amount_vs_prior20` 数量。二者可能不同，但当前表没有单独的 `amount_ratio_valid_count`，M10 也没有金额 A 的最低有效成员门槛。

#### 缺陷 5：成员变更的可比性没有进入代理合同

中位数虽然比总和更不受成员数量影响，但新增/删除成员仍会改变参与中位数的样本构成。若新成员大多是高活跃股票，A_proxy 也会改变，仍不能把它解释成同一批股票的资金扩张。

#### 缺陷 6：主字段名称不足以表达代理语义

`sector_cycle_daily.amount_vs_prior20`、`stock_technical_daily.amount_vs_prior20` 使用了同名字段，但前者是成员个股比值中位数，后者是单只股票比值。若没有额外 basis 元数据，API 使用者容易把两者当作同一层级指标。

#### 缺陷 7：当前 3 日变化是代理值的差

`amount_change_3d` 目前是 `A_proxy[t] - A_proxy[t-3]`。它不是板块总金额的 3 日变化，也不是 3 日金额均值相对前 20 日均额的重新计算值。若继续保留，字段说明必须写清楚。

## 6. 一个样本同时展示两种答案

假设前 20 个基准日每只股票的成交额均为 100，今日有 3 只成员：

| 股票 | 今日金额 | 个股金额比 |
|---|---:|---:|
| A | 300 | 3.0 |
| B | 100 | 1.0 |
| C | 100 | 1.0 |

则：

```text
当前代理：A_proxy = median(3.0, 1.0, 1.0) = 1.0
```

如果过去 20 日板块固定成员的日总额均为 300，今日板块总额为 500，则：

```text
板块聚合：A_doc = 500 / 300 = 1.666666...
```

在 `NEW` 门槛为 1.10 时：

- 文档字面方案会认为金额条件命中；
- 当前代理不会认为金额条件命中。

两者都可以从各自公式推导出结果，但它们表达的业务判断不同：

- `A_doc`：板块总交易活跃度是否扩张；
- `A_proxy`：典型成员的交易活跃度是否扩张。

再看成员数量变化：昨日 2 只股票各为 100，今日增加第 3 只，三只仍各为 100：

```text
板块总额比 = 300 / 200 = 1.5
成员个股比中位数 = median(1, 1, 1) = 1
```

这正是需要 Astra 决定的核心问题：**M10 的“金额扩张”究竟要把成员规模变化算进去，还是只看可比成员的交易活跃度变化。**

## 7. 建议的综合定稿方向（请 Astra 裁定）

### 7.1 推荐优先方案：板块级可比成员聚合比作为正式 A

建议将 M10 正式 A 定义为板块级、排除当前日的、同一可比成员集合上的聚合金额比：

```text
U[s,t] = t 日板块 s 与比较窗口满足可比要求的成员集合

S[s,t] = Σ raw_amount[i,t]
         （i ∈ U[s,t] 且 t 日金额有效）

D[s,t] = mean(S[s,u])
         （u 为 t 前连续 20 个主交易日，使用同一 U[s,t] 计算）

A[s,t] = S[s,t] / D[s,t]
```

这里的“同一 U”是为了避免成员新增/删除把成员数量变化伪装成资金扩张。若历史成员快照和历史行情不足以构造 U，A 应为 NULL 并附数据不足原因，不应静默退回当前代理继续触发主线分类。

该方案的效果是：

- M10 A 真正回答“同一批可比成员的板块交易活跃度是否扩张”；
- 原始板块金额 `member_amount_sum` 仍可用于展示板块实际当日规模；
- `member_amount_sum` 与 `A` 的业务意义分离，不再把总额和归一化指标混成一个字段；
- 成员变化可以单独通过 M9 的成员变化、进入/退出和覆盖字段解释；
- 数据不足时不会产生假阳性主线状态。

### 7.2 推荐的字段和质量信息

如果采用推荐优先方案，建议新增或明确以下字段，避免继续复用含义不清的同名字段：

```text
member_amount_sum                  当日全体纳入成员有效金额之和，单位元
amount_valid_count                 当日原始金额有效成员数
amount_comparable_member_count     用于 A 的可比成员数
amount_comparable_coverage         可比成员数 / 目标成员数，比例 0–1
sector_amount_vs_prior20           正式 M10 板块聚合金额比
sector_amount_prior20_mean         正式 A 使用的前 20 日板块基准均值，单位元，可选
sector_amount_basis                例如 COMMON_MEMBER_FIXED_UNIVERSE
amount_quality_code                例如 OK、INSUFFICIENT_HISTORY、LOW_COVERAGE、UNKNOWN
```

若为兼容旧预览结果而保留旧字段，不能把旧字段静默改义。可以保留：

```text
amount_vs_prior20_proxy_median     当前成员个股金额比中位数，仅诊断/对比用途
```

正式 M10 主线 predicates 应只引用定稿后的 `sector_amount_vs_prior20`，或由 Astra 明确批准继续引用代理字段。

### 7.3 成员历史不可用时的处理

当前代码注释已说明：预览日期之前缺少完整 point-in-time 历史成员口径。因此在正式聚合方案无法构造同一可比成员集合时，建议有三种显式状态：

| 状态 | 正式 A | 当前代理 | M10 金额条件 |
|---|---|---|---|
| 可比成员和 20 日基准完整 | 计算 | 可同时输出诊断 | 允许参与分类 |
| 可比成员不足，但代理可算 | NULL | 可输出 | 金额条件为 UNKNOWN，不作为正式命中 |
| 20 日历史不足或分母非正 | NULL | 可能也为 NULL | 金额条件为 UNKNOWN |

如果 Astra 认为预览阶段必须继续出状态，也应把 `A_proxy` 改名并标注为 `DIAGNOSTIC_PROXY`，不能在 API 和 UI 中继续把它显示成无条件的“板块金额 A”。

### 7.4 可接受的替代方案：正式采用成员个股比值中位数

如果 Astra 认为 M10 真正想表达的是“典型成员的活跃度”，也可以正式采用当前算法，但必须把文档和字段改成准确语义：

```text
A[s,t] = median(
    raw_amount[i,t] / mean(raw_amount[i,t-20:t-1])
    for valid member i in s at t
)
```

此时必须同时完成：

- 将 M10 文档的“板块成员金额 / 前20日均额”改为“有效成员个股金额比中位数”；
- 将阈值 1.10/1.20 的文字解释改为“典型成员活跃度扩张”，而不是“板块总金额扩张”；
- 增加 `amount_ratio_valid_count` 和最低有效成员门槛；
- 明确新成员/删除成员会影响中位数的样本构成；
- 正式字段建议改名为 `member_amount_ratio_median_vs_prior20`；
- `amount_change_3d` 明确为该中位数的 3 日差值；
- 给出版本号，例如 `MAINLINE_AMOUNT_MEMBER_MEDIAN_V1`，不要继续伪装成板块聚合口径。

该替代方案的效果是保留当前计算成本和稳定性，并降低成员规模、单只极端股票对指标的影响；代价是它不再代表板块总成交金额扩张。

## 8. 无论采用哪条方案，都必须统一的窗口和缺失规则

Astra 定稿时至少需要明确以下共性规则：

### 8.1 当前日是否进入分母

必须为“不进入”。旧 `amount_ratio20` 继续保留其含当日的旧语义，新 M10 指标不得覆盖旧字段。

### 8.2 20 日窗口是否允许跨缺失日扩展

建议沿用 M8A 的强规则：使用前 20 个主交易日位置；窗口中缺少必要金额观察时，结果为 NULL，不向更早日期扩展凑满 20 个样本。

如果要采用“前 20 个有效日”并允许向前扩展，必须单独升级合同，因为这会改变当前 M8A 的窗口一致性原则。

### 8.3 分母为 0、负数或 NULL

建议统一为：

```text
分母 <= 0 或不存在 -> A = NULL
```

不能将其改为 0，因为 0 代表真实的无金额比值，而不是“不知道”。

### 8.4 金额为 0、停牌和未知

建议至少区分：

- 正常且金额为正：可进入金额聚合；
- 金额为 0 且含义是无成交/停牌：是否进入分母需由合同明确，不能和未知混淆；
- NULL、缺行、质量不合格：未知，不得按 0 聚合。

### 8.5 3 日变化

必须在合同中二选一并命名准确：

```text
amount_change_3d = A[t] - A[t-3]
```

或：

```text
amount_ratio_3d_vs_prior20
  = mean(S[t-2], S[t-1], S[t])
    ÷ mean(S[t-22], ..., S[t-3])
```

如果同时需要两者，必须用两个不同字段，不能把“3 日差值”称为“3 日金额比”。
