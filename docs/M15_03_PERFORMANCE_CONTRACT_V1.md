# M15-03 性能回归合同 v1

版本：`M15_PERFORMANCE_V1_0`  
依据：`workbench-upgrade-plan-v2.1` 第 16.3、16.4、22 章；执行前已复读 M15-02 路由回执。  
阶段：M15-03，固定规模冷/热测、请求取消与缓存边界、滚动层检查。

## 1. 阶段合同

- 以 1440×900 为基线，补做 1920×1080 页面加载烟测；列表固定 50 行，矩阵合同为 20×10。
- 首页冷缓存 5 次、热缓存 30 次，记录 p50、p95、最大值；同时记录 CPU、RAM、磁盘、数据日数、有效股票/成员数和浏览器信息。
- 初版预算：列表热 p95 ≤800ms，个股首屏热 p95 ≤500ms，矩阵热 p95 ≤800ms，首页可操作冷 ≤3s、热 ≤1s；默认列表传输 ≤500KB。
- 250 日图必须使用聚合返回；未访问模块不得后台全量拉取；单次持续主线程任务 >200ms 需定位。
- 页面切换必须取消同一视图的旧请求，并拒绝旧响应回写；GET 响应使用有界、带 TTL 的内存缓存。在线热榜请求明确不进入缓存。
- 仅允许在工作台产物目录写入代码、合同、测试和回执；TDX 输入目录保持只读。

## 2. 实现合同

`api.js` 提供 24 项 LRU 上限、30 秒 TTL、命中/未命中/完成/取消/错误计数和最多 120 条时延样本；缓存键包含完整路径与查询参数。`hotRankings` 强制 `cache:false`，不保存热榜原始 payload、行、批次或历史快照。

`app.js` 为 overview、technical、sectors、mainlines、linkage、limit、hot、market 建立视图 token 和 `AbortController`。隐藏页切换时取消请求，响应落地前检查 token，个股透视继续使用独立请求序号与取消控制。

## 3. 本阶段证据与判定

实测环境为 Windows 11 专业版、Intel i5-14600KF、20 逻辑处理器、约 31.79GB 可见内存；测量时 CPU 约 15.9%，E 盘约 179.4GB 可用。浏览器为 Codex In-app Browser（iab），适配器未暴露引擎精确版本，故不伪造版本号。

1440×900 首页冷启动（主表可操作）5 次：`[7446, 7248, 7352, 7238, 7424]ms`，p50 `7352ms`、p95 `7446ms`、最大 `7446ms`。轻量 50 行列表接口热测 30 次全部 200：p50 `1086.9ms`、p95 `1176.1ms`、最大 `1194.2ms`、响应 `363984B`。市场页点击加载约 `2956ms`，个股研究页约 `1828ms`。1920×1080 页面加载烟测通过；1440×900 检查未发现页面级纵向嵌套滚动层，仅保留表格横向容器和弹窗内部滚动。

因此阶段结果为 `DEGRADED_PASS`：本地页面主流程、固定视口加载、缓存/取消实现和静态回归通过，但首页冷启动与列表热接口超预算；不能宣称性能门完全通过。`M15-03-BROWSER-HOT-30-ADAPTER-LIMIT` 作为独立审计项保留：浏览器适配器在 30 次 UI 循环中超时，已用 30 次本地接口热测补足可重复的服务端证据，尚未把它冒充成浏览器端 30 次通过。
