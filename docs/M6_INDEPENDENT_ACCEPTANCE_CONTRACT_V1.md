# M6 独立验收合同 V1

## 目标

以两个真实交易日的封存发布为对象，形成可由独立验收方复核的双轨证据包和最终报告。M6 只验收既有实现，不调整模型规则、阈值或历史封存数据。

## 前置门禁

- `reports/upgrade_m5/M5_OPERATIONS_RECEIPT.json` 必须为 `FULL_PASS`，且 `next_stage` 为 `M6_INDEPENDENT_ACCEPTANCE`。
- M0 至 M5 的阶段收据链必须存在并保持通过状态。
- `D:/new_tdx` 及配置中的所有 TDX 源目录继续作为只读输入。

## 双轨证据

1. 数据与身份轨：对两个真实交易日核验 publication、source、computation、render、membership 身份，核对股票、板块、候选、五类队列、成员关系和 Forward 数据的日期隔离及数量。
2. 服务与交互轨：对同两日核验日期切换、接口分页、五类队列、友好证据、板块成员数量、板块内名次、双向联动、空状态和运维入口。

## 性能与故障验收

- 记录查询冷/热态延迟、返回行数及分页上限；不得用一次性全量 DOM 加载替代接口查询。
- 复核发布幂等、崩溃无半发布、备份恢复、迁移准备和受控重启回退证据。
- 性能结果是实测记录，不外推为概率或未来承诺。

## 独立性与结论

- 开发方可以生成候选证据包和内部预检结果，但不得自行签发 `EXTERNAL_AUDIT_PASS`。
- 独立验收方必须记录验收人/执行主体、环境、时间、命令、原始输出摘要、问题清单和结论。
- 只有独立验收结论为 `EXTERNAL_AUDIT_PASS`，且问题清单无阻断项时，才允许切换正式入口。
- 在此之前，M6 状态只能是 `IN_PROGRESS`、`AWAITING_EXTERNAL_AUDIT` 或 `BLOCKED`。

## 禁止事项

- 不使用网络行情、外部复权服务、未来数据、自动交易或概率表述。
- 不修改 TDX 源目录，不覆盖历史封存发布，不因验收结果调参。
- 不以测试数量、开发方 PASS 或页面截图替代独立复核。
