# M9 本地通达信行业层级维护说明

合同 ID：`TDX_SECTOR_HIERARCHY_V1_1`

## 1. 页面现在读什么

行业父子关系不是 API 每次临时按名称或代码推断，而是由本地构建任务生成的不可变静态表：

- `tdx_sector_hierarchy_versions`：记录层级合同、来源文件摘要和版本；
- `tdx_sector_hierarchy_nodes`：记录每个板块的父板块、层级和关系依据；
- `analysis_snapshot_hierarchy`：把一次分析快照绑定到当时使用的层级版本。

M10 页面只读取当前发布快照绑定的版本。概念、风格和其他非行业板块保持平级；地区板块不进入公共主线列表。

## 2. 本地数据变化时怎么处理

每次本地 TDX 元数据进入 `data/input_staging` 后，构建任务会计算 `tdxhy.cfg`、`tdxzs.cfg`、`infoharbor_block.dat` 的摘要，并把摘要与成员输入一起纳入层级版本指纹：

1. 摘要和节点内容没有变化：复用已有层级版本；
2. 任一来源或节点内容变化：创建新的 `tdx-hierarchy-v1.1-*` 版本；
3. 新分析快照绑定新版本，旧分析快照继续绑定旧版本；
4. 不覆盖旧版本，因此历史页面仍能按原始口径复现。

这意味着“静态读取”并不意味着永久不更新，而是“构建时定期维护、运行时按快照读取”。维护动作可以由本地定时任务重新运行 M8/M9 构建；只有本地 TDX 输入变化时才会产生新的层级版本。

## 3. 当前边界

行业父子关系的当前规则是：在同一行业代码集合中，使用已存在的最长代码前缀作为父级；不存在前缀父级的行业节点为一级行业。这个关系的依据会写入 `relation_basis`，不会伪装成 TDX 原生明确的父子字段。
