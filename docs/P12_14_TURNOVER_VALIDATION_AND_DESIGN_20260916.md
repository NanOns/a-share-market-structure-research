# P12-14 换手率来源验证与系统使用设计

## 阶段合同与结论

本阶段执行 `P12_14_EASTMONEY_CANDIDATE_TURNOVER_V1`，范围是本地V3.3初筛后的可选换手率增强、来源小样本验证、目标交易日绑定和失败降级。阶段结果为 **`DEGRADED_PASS`**：工程合同、单位修正、能力门和使用边界通过验收；2026-09-16对当前V3.3研究包20只沪深候选执行一次批量请求时，源端以 `RemoteDisconnected` 主动断开，因此当前来源能力保持关闭。

该失败不会阻断本地一键生成，也不会改变候选、类别、分数、排名、研究包身份或170日历史数据。机器证据见[阶段回执](../reports/p12_14/p12_14_turnover_probe.json)。

## 已验证事实

- 东方财富个股页面明确展示换手率、成交量、成交额和流通市值，但网页正文依赖动态接口。
- `SZ.002491` 的单股当前接口在本次验证中返回 `f168=2270`，对应22.70%；同一来源日K接口在2026-09-15记录换手率22.70%。当日成交量字段为2,670,494手，转换为267,049,400股；结合流通市值和收盘价反推的流通股数，得到的换手率同样约为22.70%。因此本合同把该字段标为 `EASTMONEY_FLOAT_SHARE_BASIS`，不冒充交易所“总股本换手率”。
- 现有适配器过去把 `f47` 直接标为股，实际A股口径是手。本阶段已在来源边界改为乘100并保留 `source_volume_unit=LOTS_100_SHARES`。
- 批量接口没有可信的行情日期字段。采集时间不能冒充交易日，`f170`也不能冒充时间。本合同要求用本地目标日的收盘价、成交额、成交量三项指纹绑定；任一不匹配即 `UNAVAILABLE`。
- 连续少量探测后出现主动断开，证实其不适合全市场或高频抓取。2026-09-16后续修正取消固定20只上限：覆盖活动V3.3研究包全部沪深候选，每批最多50只、顺序执行，任一批失败即停止；每批8秒超时、零重试、200 KB响应上限，不保存原始响应。

## 在系统中的使用

V1只在本地筛选完成后运行，顺序为：冻结本地研究包 → 取全部沪深候选 → 按50只分批增强 → 与本地目标日指纹绑定 → 形成证据和换手活跃度百分位 → 对 `QUALIFIED_UNRANKED` 在同一主类别、同一选择模式内生成二级序号。核心V3.3评分、类别排名和准入结果保持不变。

允许用途：

1. 候选详情展示“换手率、来源口径、能力状态和采集时间”。
2. 证据抽屉展示来源为东财流通股口径，并说明它是外部增强。
3. 生成诊断标签和影子统计，例如后续观察高换手候选的前向表现；在形成足量样本前不设好坏阈值。
4. 来源失败时显示“换手率暂不可用”，数值保持空，不填0，也不隐藏候选。

禁止用途：

- 不参与V3.3候选准入、四类场景判断、分数或排名。
- 不作为发布READY门，不阻断本地一键生成。
- 不用于170日历史回填；实时网页值不能补成历史PIT数据。
- 不由成交量、成交额或量比替代缺失换手率。
- 不支持北交所；北交所候选明确标记 `UNSUPPORTED_MARKET`。

如果以后要把换手率升级为正式算法因子，应另开合同，取得带生效日期的历史流通股本或自由流通股本数据，在本地按 `成交股数/明确股本分母` 计算，并完成公司行为、股本变更、停复牌、缺失覆盖和前向效果审计。当前东财候选增强不能直接升级为正式排名因子。
