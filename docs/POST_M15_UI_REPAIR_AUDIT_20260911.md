## 需要二次确认或专项审计的事项

### A. M11 关联联动的语义模型

现有 M11 结果把股票与板块关联起来，但“通达信内部板块/标签”和研究所需的行业、概念并不是同一个语义层。建议保留原始关联行作为不可变来源，同时在关联合同中显式区分 `INDUSTRY`、`THEME` 与内部标签；行业和概念分别计算成员名次与强势关联，不跨类型合并排序。若要支持“更多板块更新”，应新增关系版本和来源时间，而不是覆盖旧快照。

需要确认：是否保留内部标签关系作为仅供追溯的辅助关系，还是从产品层完全隐藏；以及是否允许行业、概念在同一筛选器中做显式并集。

### B. M14 在线增强的启用方案

当前在线增强仍按 fail-closed 设计：热榜是请求时读取，不写入本地快照、历史结果或研究排序；报价、涨停原因等能力分别受来源合同和能力门控制。截图中的“不可用（无已验证来源）”表示来源未完成可审计验证，不是前端丢失数据。

建议按数据集分别建立 `source_contract`、能力状态、`observed_at/source_as_of` 和失败原因：热榜、最新报价、当日涨跌幅/成交额、涨停原因各自独立；请求有超时、条数和频率上限；失败时保留本地首屏并显示原因。热榜仍只保留请求结果，不改变本地快照身份。启用任何具体来源前需审计来源稳定性、字段含义和授权边界。

### C. M13/M8C 涨停梯队与晋级

当前本地快照中的部分参考价仍是 `APPROXIMATE/UNKNOWN`，规则引用为 `UNREGISTERED`；虽然规则版本表中存在已核验规则，不能因此反推每一行的精确前收、除权处理、上市阶段或风险板规则。故当前 6177 行保留未知是数据能力门的正确结果。

建议单独完成：逐证券绑定可审计前收/除权参考、证券元数据和适用规则；对每个参考行记录来源快照、规则 ID、有效期和验证状态；再重建 M13 并验收 `reference_bound_rows`、`rule_bound_rows`、`known_limit_state_rows`、`ladder_rows`、晋级合格分母等数量。不能直接从同花顺或其他平台复制结果，也不能将未知填成 0。

### D. 市场历史聚合图的可读性

截图中的图形并非单纯前端丢线：当前快照可用历史窗口只有 3 个交易日，涨跌停字段存在 NULL；同时市场计数、成交额和覆盖率单位不同，图表按系列自身范围绘制，叠加后容易显得抽象。

建议后续把每个系列的单位、有效点数、缺失点数直接显示在图例/卡片中，并提供“原始数量 / 覆盖率”切换；当有效日期少于 5 个时显示短窗口警告，而不是让用户把短线段误认为完整趋势。此项属于图表口径设计，不应通过补零解决。

### E. 既有独立审计项

M10 Amount A、M13 物化对齐、M13/M8C 输入物化、M14 来源与条款门仍按原回执作为独立审计项跟踪。本次只修复了 M13 快照层级绑定和页面表达，没有把这些审计项误标为已关闭。
