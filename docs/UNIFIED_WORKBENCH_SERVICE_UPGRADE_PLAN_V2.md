# 统一工作台升级方案 V2

> 后续 M7–M15 完整实施入口为 [完整实施方案 v2.1](WORKBENCH_M7_M15_IMPLEMENTATION_PLAN_V2_1.md)。2026-09-10 金额专项已补齐其第27章：板块聚合金额 A 与成员个股比中位数分离，正式实现待验收。本文保留为平台架构基线，不与后续业务合同并列定义 M10。

版本：2.0；状态：平台架构基线。V2 服务入口已可用，M7–M10 当前按独立预览能力交付；本文不代表 M7–M15 全部功能已经上线。

开发分支：`feature/unified-workbench-service`。本文取代 V1 的实施口径，V1 保留作历史记录。范围包括本地数据库、自动日线下载、动态元数据、统一工作台、配置迁移、自动清理和后台重启。

## 1. 用户最终获得什么

一个固定工作台入口，完成“检查更新 → 下载并校验 → 生成结果 → 切换日期 → 查看板块个股 → 管理存储与配置”。关闭浏览器不取消任务；重新打开能恢复任务进度。终端仍可负责元数据更新，其是否确实完成更新由输入检查决定。

- 首页同时展示板块和个股；保留五类 V2 独立队列。
- 日期切换覆盖已发布数据库结果，即使该日原始快照已清理。
- 板块显示当日单日收益、上一交易日收益及百分点变化，明确计算口径。
- 新股、新板块和成员变化自动发现，缺历史的新股可查询并解释暂不入选原因。
- 数据库正式结果长期保存，原始快照默认仅保留最近三个交易日。
- 所有路径、缓存配额、保留策略可配置；重启后自动重连。

## 2. V1 需要纠正的设计

| V1 问题 | V2 决定 |
|---|---|
| 两次哈希一致就视为最新元数据 | 分开记录稳定性、解析完整性和新鲜度；无法证明新鲜时显示未知 |
| 通达信进程在线等同完成更新 | 在线仅是辅助信号，更新机制及各文件时序必须实测 |
| 上一成功发布日期等同上一交易日 | 按主交易日历定位；缺失则显示缺失，不能拿更早日期冒充 |
| 原始快照清理后仍可完整复算 | 明确区分结果查询、逻辑证据核验和原始字节重算 |
| 新旧服务同时打开数据库 | 单一数据库所有者；停写、关闭连接、交接后再接管 |
| checkpoint 后直接复制活动数据库 | 用经演练的一致性备份流程；首版在维护窗口关闭连接再复制 |
| 成员每天完整重复写入 | 按成员快照身份去重，发布日期引用快照 |
| 阈值、目录、展示代码混成一个身份 | 分开经济模型、输入、执行、展示和配置身份 |
| 固定一天的数量校验当前数据 | 固定样本回归与动态真实数据验证分开 |

## 3. 范围与来源约束

只读规则继续适用于 `D:/new_tdx` 及配置的终端源目录。下载器写项目托管暂存区，不覆盖终端目录。用户已要求官方盘后下载，此项是原“禁止网络数据”约束的明确限定扩展：仅允许核验过的通达信官方日线来源；实施阶段同步更新项目约束，其他外部行情、外部复权和交易功能仍不启用。

官方页面说明提供个人版日线完整包，并要求更新日期变为当日后下载；没有在该页面承诺全部元数据来源或固定更新时间。链接解析、重定向主机、包体格式、体积和更新时间列为 M0 实测项。[通达信官方说明](https://www.tdx.com.cn/article/vipdata.html)

“生成今日数据”若官方未更新，返回“等待官方更新”；周末不能把自然日强行当交易日。页面分别显示请求日期、包声明日期、包内交易日和最终发布日期。默认不在未授权时无限轮询，自动检查可在设置中开启并限制频率、时段和重试次数。

## 4. 服务架构和数据库选择

采用本地工作台 API + 一个数据库所有者进程 + 一个受控计算子进程 + 轻量启动监督器。计算进程只读封存输入、输出有界临时结果；不直接连接正式数据库。API 在数据库所有者进程内执行参数化查询，所有写入排队。首版明确禁止多个 Web worker 直接打开同一个库。

DuckDB 作为默认分析存储；并发设计采用单进程管理读写连接，不假设独立进程可同时读写数据库文件。[DuckDB 并发说明](https://duckdb.org/docs/current/connect/concurrency)

不声称两百万行是全项目年增量：股票每日结果约为证券数 × 交易日数，另有队列、多周期 Forward、成员和历史价格。现有标准化历史约千万级行数，应分别测量。DuckDB 与 MySQL 的最终取舍以 M0 实测为准；已有 MySQL 不需卸载。本版本不同时维护两套生产数据库。

局域网访问本身不必迁移数据库；只有需要独立数据库服务、多写者或数据库级多用户管理，才评估 MySQL。Repository 隔离查询语义，迁移仍需要类型、SQL 和性能验证，不承诺无成本切换。

## 5. 输入快照与元数据一致性

日线与元数据独立采集，发布时绑定为一个 `source_bundle_id`：包身份、元数据快照、主交易日历、解析版本、目标交易日。计算全程锁定这一输入包。

下载：HTTPS 来源校验、连接与读取超时、有限重试、断点续传需验证 ETag/范围语义；页面返回 HTML 错误不能当 ZIP。自算 SHA256 标识收到的字节，不能冒充官方签名。解压拒绝路径穿越、绝对路径、链接、Windows 重解析点、大小写冲突；限制条目数、总展开字节和压缩比。

解压后验证日线记录长度、日期顺序、重复日期、OHLC 基本约束、主要指数和三市场覆盖。不得为适应新一天输出数量而调松现有模型阈值。Phase 0 必须先产生 FULL_PASS、DEGRADED_PASS 或 BLOCKED；BLOCKED 禁止后续扫描，DEGRADED_PASS 仅按合同允许的降级处理。

元数据捕获：

1. 枚举完整文件集并采集 manifest A。
2. 稳定窗口后确认源集合未变化，复制到暂存区。
3. 重新采集源 manifest B，与 A 和副本逐文件比较；变化则废弃重试。
4. 对证券、板块定义和成员引用做交叉一致性检查。
5. 记录稳定性 PASS、结构完整性 PASS、新鲜度 CONFIRMED/UNCHANGED/UNKNOWN。

文件 mtime 和进程在线不能证明内容是当日最新，也不能保证多文件属于终端同一次更新。首次接入必须观察真实终端更新过程，建立版本化新鲜度规则；若没有可靠更新完成信号，应明确剩余不确定性。文件多日未变不自动视为过期；已知更新失败、必要新证券映射缺失、引用冲突则阻断。

## 6. 新股、新概念与成员历史

实体使用来源和稳定代码标识，名称不作主键。新股发现、可读价格、历史长度充足、正式候选四个状态分开。所有发现证券可在工作台检索；未通过门槛说明具体缺失，不补造因子。

新概念自动进入目录，但类型、角色、有效覆盖和排除规则仍需满足合同才能排名。同名不同代码分开；代码疑似复用进入待核验。单次缺失标记 SOURCE_ABSENT，不能直接断言退市或板块永久停用。

保存观察时间、目标交易日、来源包和发布版本；历史页面绑定当时已封存成员快照。名称变化、加入、退出可追踪，不把首次观察日包装成官方生效日，不回填历史 PIT。

元数据变化页提供新增证券、新板块、改名、成员加入/退出和异常清单；成员骤变触发完整性复核，阈值需合同化，不临时拍脑袋忽略。

## 7. 数据模型与发布事务

业务日期使用 DATE；事件时间统一存 UTC、页面显示北京时间。核心结果按 `publication_id` 引用，不用“当前文件路径”关联历史。当前版本是数据库指针，同日期可以有审计修订，日常只显示最终成功版本。

| 数据组 | 表及关键约束 |
|---|---|
| 任务 | jobs、job_attempts、job_events；任务键唯一，状态迁移可重放 |
| 输入 | source_packages、source_files、metadata_snapshots、source_bundles；内容身份去重 |
| 发布 | publications、publication_heads；日期/修订唯一，head 仅指向成功版本 |
| 业务结果 | market_daily、sector_daily、stock_daily、candidate_daily；publication_id + 实体代码唯一 |
| V2 | structure_details、queue_memberships、unified_board；队列组合键唯一、一股一板行约束 |
| 元数据 | security_versions、sector_versions、membership_snapshots、membership_entries；发布引用快照 |
| Forward | observations、outcomes、state_transitions；原观察与成熟期、价格口径、修订身份绑定 |
| 运维 | config_versions、storage_objects、leases、cleanup_jobs、backup_catalog、audit_receipts |

先计算到隔离暂存区，再校验关键字段、来源、模型身份和收据；随后单个事务写结果、观察、到期结算及发布头。提交前失败整体回滚，提交后通知失败不回滚已成功数据，任务恢复时按发布键找回结果。

幂等键包括目标交易日、输入包身份、经济模型及计算合同；展示代码变化只刷新页面缓存，不新增观察。异常中断重试新建 attempt，不覆盖旧证据。Forward 保留入场观察及结算必需价格、复权口径，不因三日缓存轮转失去长周期结果所需状态。

旧文件 SHA256 与数据库逻辑摘要分开保存。逻辑摘要合同定义列顺序、主键排序、NULL、日期、浮点和字符串序列化；不把 Parquet 字节哈希当成数据库内容哈希。禁止二者值不同就判数据不一致，也不能只比行数判断迁移成功。

## 8. 板块当日与前日对比

默认名称使用“成员日收益中位数”，避免被理解成通达信板块指数涨幅。原始价格来源与复权口径写入字段说明。官方板块指数涨幅若以后支持，应作为独立指标和合同，不能混入现有模型。

- t 的日收益使用同一 t 输入版本的相邻主交易日有效价格计算。
- 上一交易日必须是日历中的 t-1；该日未发布就显示“上一交易日未生成”，可额外展示“最近有记录日期”，不冒充前日。
- 差值单位为百分点，例如 +2% 与 -1% 的差为 +3 个百分点。
- 新板块无前日记录显示“新收录”；缺失或覆盖不足显示 NULL 原因，不能归零。
- 各日收益按各自成员快照；成员变动数量和“成员口径变化”提示同时展示。
- 各类型独立排名；涨跌排名与既有 20 日强度排名分列。经济值并列同名次，代码仅稳定显示顺序；排名上升定义为前日名次减当日名次。
- 成员及覆盖变动下的对比是描述，不宣称是固定成分指数收益。

新增单日指标及排名有独立展示合同，不改变候选和 V2 经济规则。若未来用其筛选候选，必须新模型版本和复审。

## 9. 工作台交互和接口契约

固定页面：今日总览、板块排行、个股排行、五类队列、双向联动、Forward、任务中心、系统设置、存储清理。首页两部分和联动作为必须通过的浏览器回归场景。

顶部展示所选日期、实际输入日、最新成功发布日。切日时所有接口固定同一个 publication_id；在切换完成前保留加载态，防止旧日期请求晚返回覆盖新日期页面。搜索、分页、排序和导出均由 API 限制规模，页面不再内嵌全量历史 JSON。

命令入口采用 POST；查询使用 GET。主要接口包括 /api/publications、/api/dashboard、/api/sectors、/api/stocks、/api/queues、/api/linkage、/api/jobs、/api/config/validate、/api/config/apply、/api/storage/preview、/api/storage/cleanup、/api/service/restart。列表返回分页和 publication_id，任务返回 job_id，错误统一返回 code、中文说明、可重试性和下一步操作。

本机监听并不等于接口无需保护：限定 Host/Origin，写操作要求会话令牌及 CSRF 校验，不接受跨站请求或任意 SQL/命令。只使用项目安装的固定任务入口，参数严格校验。

任务进度显示阶段和已完成/总量；未知总量就显示正在处理，不能伪造百分比。关闭页面不停止后台；重复点击返回同一任务。可在下载和计算安全点取消，提交事务时显示等待完成。

## 10. 三交易日清理与证据保留

原始快照默认最多三个已完成交易日；同日多次修订只保留最终需要的一份物理快照。内容相同的元数据按身份复用。原始字节清理后保留来源 manifest、逻辑摘要、成员版本和正式结果。

明确能力：清理后历史浏览和数据库证据核验继续可用；缺少原始字节的历史全流程重算不保证可用。界面记录 RAW_AVAILABLE / RAW_PRUNED，不声称保存哈希就能恢复原始文件。历史重算需获取相同字节或明确生成新输入版本。

| 对象 | 默认政策 |
|---|---|
| 成功 ZIP | 0 份，快照验证成功后清理，减少完整包重复占用 |
| 原始日线/元数据快照 | 最近三个完成交易日；当前任务引用期间禁止删 |
| 下载失败及解压残留 | 及时清理；诊断样本最多 3 天且受字节配额限制 |
| 中间计算缓存 | 校验入库后清理，复用缓存最多三交易日且有容量上限 |
| 页面/API 缓存 | 有界 LRU，按 publication_id 和展示版本失效 |
| 普通日志与详细事件 | 30 天且限制单文件与总字节 |
| 数据库一致备份 | 最新三份，支持独立磁盘配置 |
| 正式结果、必要 Forward 状态、证据摘要 | 长期保存 |

新一天下载会短暂需要“三个已发布快照 + 一个在途暂存”的空间，页面必须明确峰值预算。若用户设置绝对空间上限，先安全删除不再需要的最旧缓存或暂停新任务，不能偷偷无限积累。失败任务不能因没有新发布日期就永久保留，按生命周期和配额清理。

storage_objects 注册管理文件与引用；维护租约、引用计数、删除状态。清理预览有计划 ID 与配置版本，执行时重新校验。只能删除受管根下登记对象，拒绝盘根、通达信目录、目录 junction/symlink 穿越及数据库引用。跨卷不能原子改名，trash 必须在目标同卷。

状态依次 PLANNED → QUARANTINED → DELETED，崩溃后可恢复；文件实际删除后才计入释放空间。磁盘满时仍要保留最小诊断记录。清理任务不得把数据库文件视为可回收缓存。

## 11. 配置、迁移和受控重启

可配置项沿用 V1 全部路径，另加 CPU/内存/临时空间预算、下载超时/重试、查询分页、快照稳定窗口、备份与自动检查时段。首次运行检测现有目录供选择；敏感机器路径写本地配置，模板进入 Git。

配置生命周期：草稿 → 校验报告 → 应用 → 生效版本。任务启动时捕获 config_revision，运行中不读取变化配置。并发设置提交用版本条件防止相互覆盖。保留数量修改即时用于下一次清理，不在当前任务中途删除输入。

路径可配置到其他磁盘，校验依据是受管目录注册与真实绝对路径，不把“必须在代码工作目录内”当硬限制。通达信只读探测；写目录仅在候选受管目录做临时探测。拒绝根目录、保护目录及相互包含造成的误清理风险。

数据库搬迁：停新任务、排空查询和写入、checkpoint、关闭全部连接、复制到新目录临时文件、校验并试开、提交新路径配置、重启；失败则恢复旧路径。不得直接移动活动库，也不能把工作库和 WAL 分开做热复制。

监督器持有稳定启动入口但不打开数据库。重启顺序：DRAINING → CLOSE_DB → RELEASE_OWNER_LOCK → START_NEW → HEALTH_CHECK → READY。浏览器自动重连，允许短暂不可用，不承诺双进程无缝写库。新进程失败由监督器重新启动旧配置；旧版本不能打开不兼容的新 schema，需恢复迁移前一致性备份。

首版固定端口，变更端口提示新地址并由启动器重开；不承诺旧地址凭空自动找到新端口。自动启动选择登录启动，按目标 Windows 权限实测，不保证所有机器免提权安装。

## 12. 身份、模型防护与故障恢复

经济模型身份包含真实影响结果的规则及合同；新配置不能通过改路径绕过输入或模型检查。执行身份覆盖代码和依赖；展示身份覆盖页面与格式。配置身份拆分经济相关字段与纯运维字段。改变清理期限不让模型失效，改变模型不冒充界面更新。

模型变更阻断新的正式观察，既有发布仍可浏览。旧观察结算不得与新模型混组。收据保存模型/输入/计算版本，任何同日重算保留修订关系。

服务启动恢复 RUNNING 但无有效租约的任务为 INTERRUPTED，验证已提交 publication 后决定返回成功或重新计算；严禁盲目覆盖封存结果。下载可有限续传，计算阶段首版允许从阶段起点重跑，数据库提交具有唯一键防重。

备份在暂停写入并关闭库后执行，备份后新位置试开和查询抽检再登记。恢复演练必须验证交易日、发布头、队列、成员和 Forward。原始缓存清理不妨碍备份恢复结果数据库，但备份不替代原始全流程重算输入。

|---|---|---|
| M0 风险收敛 | 官方下载协议样本、终端更新实测、容量基准、旧测试分类、身份清单 | 未验证能力列明，不将猜测写成 PASS |
| M1 数据底座 | schema、repository、逻辑摘要、历史导入、单所有者 | 固定日期迁移逐字段一致、重复导入无重复 |
| M2 服务与只读页面 | 统一启动器、日期切换、首页两部分、排行与联动 | 浏览器真实点击、跨日期无串数据 |
| M3 自动输入 | 下载、安全解压、稳定元数据、动态成员、只读 source bundle | 半包/变更中/新股/新概念/引用缺失故障测试通过 |
| M4 一键发布 | 后台任务、事务发布、幂等及 Forward 结算 | 崩溃恢复无半发布、同日重试无重复观察 |
| M5 运维功能 | 配置中心、跨盘迁移、三日清理、受控重启、备份恢复 | 路径逃逸/磁盘满/租约/重启失败回退演练通过 |
| M6 独立验收 | 两个真实交易日双轨证据、最终报告 | EXTERNAL_AUDIT_PASS 后切换正式入口 |

先交付能查历史的统一工作台，再接自动下载，避免一次替换全部链路。开发继续在升级分支；main 稳定入口保留直到 M6。迁移不应直接修改现有封存数据。

八项已暴露历史测试失败须在 M0 分类确认，不能统一改成当天数量：固定日期断言读取固定证据，动态测试验证规则与输入，破坏性测试只在临时副本运行；集成身份、Forward 零结果等失败逐项核查。
