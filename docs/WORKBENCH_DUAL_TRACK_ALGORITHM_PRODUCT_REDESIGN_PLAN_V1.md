# 工作台本地研究＋在线事件双线审计与目标版本升级方案 V1

> 文档状态：实施前主方案，不代表代码已经修改。  
> 目标：把工作台从“展示大量历史强者”改造成“少量、分阶段、可解释的每日研究工作台”。  
> 数据原则：项目允许联网；在线数据负责当日事件事实，本地数据负责趋势、位置、持续性和历史研究。  
> 关系：本文吸收并扩展《工作台目标版本：在线事件数据融合改造实施方案 V1》，作为新的总方案；原 M7–M15 只作为已建底层能力和迁移参考，不再作为产品功能的直接实施顺序。

## 1. 执行结论

现有工作台的核心问题不只是缺在线数据，而是研究对象定义错误：

1. **把历史强度等同于当前值得研究。** 板块 20 日强度仍高，即使今天大跌、宽度塌缩、成员流失，首页仍叫它“强势板块”。
2. **把累计涨幅最大等同于核心个股。** 连续上涨十几天、位置极高、追涨风险明显的股票仍被排在“核心观察”。
3. **把全量候选池叫优先研究。** 最新发布有 1,187 只候选，已经失去“优先”的含义。
4. **板块和个股只做静态排名，没有生命周期。** 用户看不到启动、确认、加速、健康趋势、首次回撤、再加速、过热、派发、退潮之间的差异。
5. **联动功能从数据库结构出发，而不是从研究动作出发。** 手输板块 ID、股票 ID、切换多个模式、查看多张表，操作路径反直觉。
6. **计算和存储与实际使用不匹配。** 每天重复物化全市场、全成员、多窗口数据，但首页真正需要的只是几十个板块和几十只股票。

目标版本必须同时引入三个正交概念：

- **强度**：过去和当前有多强。
- **阶段**：处于启动、延续、回撤、再加速还是退潮。
- **研究适配度**：当前是否值得进入有限研究清单。

高强度不必然有高研究适配度。处于绝对高位的强股可以进入“强势但过热”观察区，但不能占用首页优先研究席位。

## 2. 双线架构

```text
在线事件线
  市场概况 ─ 涨停/炸板/跌停 ─ 最强题材 ─ 人气/飙升/板块热榜
       │             │              │
       └─────────────┴──────┐       │
                             ▼       ▼
                       研究融合层
                    阶段 + 位置 + 新鲜度
                             ▲
                             │
本地研究线
  日行情 ─ MA/RPS/新高 ─ 板块周期/留存 ─ 五类结构/成交额
```

在线和本地字段不得混成来源不明的总分。融合结果必须保留分量、来源、时间和缺失状态。

## 3. 现状审计

### 3.1 首页强势板块存在“历史强、今天弱”误判

当前 `_overview_strong_sectors` 从 `sector_cycle_daily` 按 `rank` 排序，对行业和概念各取前 10。查询虽然读取了 `board_quote_ret1`、`member_ret1_median`、`breadth_ret1`、`diffusion_state`，但没有当前日否决、退潮分组或位置风险判断。

因此以下板块仍可能进入“强势板块”：

- 20 日 RPS 仍高，但今日板块指数和成员收益明显为负；
- 上涨成员宽度骤降；
- 成交额放大但价格下跌，可能是分歧或派发；
- 强势成员留存率快速下降；
- 排名仍靠前，但 1/3/5 日排名持续下滑；
- 在线事件池已经没有涨停或强势成员。

结论：现有名称应立即在产品定义上废止。算法升级前只能叫“20 日相对强度前列”，不能叫“当前强势板块”。

### 3.2 主线分类没有形成可用收敛

最新分析快照中，`mainline_daily` 有 543 个板块处于 `OBSERVING`，11 个为 `DATA_INSUFFICIENT`。当前分类虽然包含 `FADING`、`HIGH_LEVEL_CONTRACTION`、`REACCELERATING`、`SUSTAINED`、`NEW` 等状态，但实际数据条件和历史覆盖导致绝大多数板块落入观察态。

主要问题：

- 以 20 日强度百分位为核心，反应偏慢；
- 当前日价格、宽度、金额和在线事件没有形成硬性阶段门；
- `OBSERVING` 既包含普通板块，也可能包含数据不全或条件接近者，信息密度低；
- 分类没有转化为“首页展示、备选观察、风险退出”三个用户层级。

### 3.3 优先研究池不是优先清单

最新发布的 `candidate_daily` 共 1,187 只：

| 等级 | 数量 |
|---|---:|
| A+ | 60 |
| A | 119 |
| B | 237 |
| C | 771 |

主要形态数量包括板块龙头 431、强势回撤 417、突破准备 210、稳健趋势 73。现有 `/api/candidates` 只是按照 `research_priority` 和 `priority_score` 对全量候选分页。即使默认每页 50，也没有解决每天有 1,187 只“优先研究”的语义错误。

### 3.4 五类结构偏重“是否符合形态”，缺少位置与时机总门

现有五类结构可以描述趋势、回撤、突破、板块领先和早期启动，但各队列独立命中后被直接汇总。缺少统一的：

- 绝对位置风险；
- 连续上涨持续时间；
- 距离 MA 与近期高点；
- 今日是否已经加速过度；
- 所属板块是否仍处于有效阶段；
- 在线事件是否具有新鲜度；
- 同一股票多队列重复命中的去重与研究席位竞争。

结果是“形态正确”被误读为“现在值得优先研究”。

### 3.5 板块—个股联动虽然可审计，但不符合人的使用路径

现有联动拆成属性库、关联联动、交叉筛选，并要求用户理解板块 ID、证券 ID、模式和不同排名口径。算法还主要依赖 20 日共同强势：剔除目标股后板块 20 日收益中位数为正、上涨占比至少 60%，目标股位于板块内前 20%。这能避免循环论证，却仍不能回答：

- 该股**今天为什么强**；
- 这个板块今天是否启动或退潮；
- 该股在板块中承担什么角色；
- 当前属于早期、健康趋势还是高位过热；
- 下一步应该查看哪组证据。

### 3.6 数据计算和存储审计

主库约 1.6 GiB，仅 5 个交易日便形成约 336 万行板块成员状态、111 万行新高、67 万行股票—板块关联和 41 万行历史结构。47 个成功分析快照反复保留近似全市场切片。

本轮不直接删除历史数据，但目标版本必须停止继续扩大错误模式：页面刷新不得触发计算；在线事件只存事件集合；首页和优先研究只物化小结果；全市场基础因子采用一次增量计算、多功能共享。

## 4. 新的研究语义

### 4.1 板块生命周期

每个板块每天只能处于以下一个主阶段，同时附强度和风险标签：

| 阶段 | 含义 | 首页处理 |
|---|---|---|
| `DORMANT` 沉寂 | 无当前强度和事件 | 不展示 |
| `EMERGING` 萌芽 | 近期首次进入强度前列，宽度/金额/事件开始扩张 | 优先展示 |
| `CONFIRMING` 确认 | 连续 2–3 日改善，强势成员扩散 | 优先展示 |
| `ACCELERATING` 加速 | 强度、宽度、金额同步快速上升 | 展示但提示节奏风险 |
| `HEALTHY_TREND` 健康趋势 | 持续较强但未显著过热 | 正常展示 |
| `FIRST_PULLBACK` 首次回撤 | 主趋势仍在，缩量回撤且成员结构未破坏 | 优先研究 |
| `REACCELERATING` 再加速 | 回撤后重新放量、宽度回升、排名改善 | 优先展示 |
| `OVERHEATED` 过热 | 短期涨幅/位置/连续加速过高 | 单列警示，不进优先研究 |
| `DISTRIBUTING` 高位分歧 | 高位放量、宽度下降、成员留存下降 | 风险区 |
| `FADING` 退潮 | 强度、宽度、事件和成员同步弱化 | 不列为强势 |
| `DATA_INSUFFICIENT` 数据不足 | 无法确认 | 不进入排序 |

“强势板块”页面改名为“板块阶段与研究机会”。强度仅是字段，不再是分类名称。

### 4.2 个股生命周期

| 阶段 | 核心特征 | 研究处理 |
|---|---|---|
| `BASE_BUILDING` 基础构筑 | MA 收敛、波动收缩、量能平稳 | 观察 |
| `EARLY_TRIGGER` 早期触发 | 突破或事件出现，位置尚不过高 | 优先 |
| `CONFIRMED_TREND` 趋势确认 | MA 与 RPS 改善，所属板块有效 | 优先/持续跟踪 |
| `FIRST_PULLBACK` 首次健康回撤 | 回撤到 MA10/20、缩量、结构未破坏 | 优先 |
| `REACCELERATION` 再加速 | 回撤后重新走强且量价确认 | 优先 |
| `EXTENDED` 延伸过度 | 连涨过久、偏离均线、接近高点且短期涨幅过大 | 不进优先池 |
| `CLIMAX` 加速高潮 | 当日和短期脉冲极强、量能异常放大 | 风险观察 |
| `DISTRIBUTION` 高位派发 | 高位放量滞涨/长阴/宽幅分歧 | 排除 |
| `BROKEN` 结构破坏 | 跌破趋势支撑且相对强度转弱 | 排除 |

### 4.3 “研究适配度”而不是“推荐买入”

研究适配度只回答“是否值得花有限时间继续查看”，不是交易建议或上涨概率。排序要优先满足：阶段可研究、位置不过热、板块有效、证据完整，然后才比较强度。

## 5. 本地板块算法 V3

### 5.1 输入

- 当日与 1/3/5/10/20 日板块收益和 RPS；
- 当日成员上涨宽度、涨停宽度、MA20 上方宽度；
- 当日成交额、相对前 20 日金额、3 日共同成员金额变化；
- 强势成员留存、进入、退出和代表股更替；
- 在线最强题材、涨停分布、板块热榜事件；
- 当前板块位置：20/60 日区间位置、距 20/60 日高点、累计涨幅和回撤。

### 5.2 当日退潮否决门

任一硬条件成立，不得出现在首页“当前有效板块”：

1. 当前数据覆盖不足 70%；
2. 当日成员上涨宽度低于 30%，且板块收益为负；
3. 3 日共同成员宽度下降达到 20 个百分点，且排名连续下降；
4. 强势成员留存率低于 40%，并且退出数大于进入数；
5. 在线事件已存在但该板块无事件成员，同时本地当日宽度和收益均转负。

第 2–5 条不能只用固定绝对阈值上线。实现时还要与板块自身近 60 日分布比较；固定门用于最低保护，分位条件用于适配不同波动板块。

### 5.3 高位与过热识别

满足以下组合之一标记 `OVERHEATED`：

- 20 日收益位于同类板块前 5%，且距离 20 日高点不足 2%，且连续上榜至少 8 日；
- 5 日收益处于自身近 120 日 95% 分位以上，成交额超过前 20 日均值 1.8 倍；
- 10 日内出现 3 次以上加速日，当前宽度不再创新高。

过热不是看空结论，但不应与萌芽、首次回撤混在同一个首页列表。

### 5.4 阶段判定顺序

按风险优先的确定顺序判断：

```text
DATA_INSUFFICIENT
→ FADING
→ DISTRIBUTING
→ OVERHEATED
→ REACCELERATING
→ FIRST_PULLBACK
→ ACCELERATING
→ CONFIRMING
→ EMERGING
→ HEALTHY_TREND
→ DORMANT
```

每一步返回命中谓词和未命中原因。风险状态优先，避免 20 日强度高同时又被归为健康趋势。

### 5.5 板块研究排序

先按阶段分组，再在组内评分，绝不把不同阶段混成一个总榜：

```text
sector_actionability =
  0.25 × freshness
+ 0.20 × breadth_quality
+ 0.15 × amount_confirmation
+ 0.15 × relative_strength_acceleration
+ 0.15 × member_retention
+ 0.10 × online_event_confirmation
```

`freshness` 衡量首次进入、排名改善和事件新鲜度；绝对 20 日涨幅不直接加分。任何位置风险只作为资格门或风险标签，不能靠其他分量抵消。

首页席位建议固定：萌芽 4、确认 4、首次回撤 4、再加速 4、健康趋势 4，共最多 20 个。某组不足时按阶段优先级补位，但过热、派发、退潮永不补位。

## 6. 本地个股算法 V3

### 6.1 统一位置风险层

在五类结构之外新增 `stock_position_state`，至少使用：

- `RET5/10/20/60`；
- `POS20/60/120`；
- `DIST_HIGH20/60`；
- 价格相对 `MA5/10/20/60` 的偏离；
- 连续收于 MA5/MA10 上方天数；
- 20 日最大回撤和真实波动；
- 量额相对前 20 日均值；
- 最近 10 日大阳/涨停/跳空的集中度。

### 6.2 过度延伸否决

满足任一组合则进入 `EXTENDED` 或 `CLIMAX`，不能进入优先研究：

- `POS60 ≥ 0.90`、`DIST_HIGH20 ≥ -0.03` 且 `RET20 ≥ 25%`；
- 相对 MA20 偏离 ≥ 15%，并连续 8 日以上收在 MA5 上方；
- 5 日涨幅处于自身近 250 日 97.5% 分位，且金额放大 ≥ 1.8 倍；
- 20 日收益中超过 60% 集中在最近 3 日，表现为末端脉冲；
- 所属主驱动板块已经 `DISTRIBUTING/FADING`。

阈值必须先做跨年份、跨板块稳定性审计；不根据未来收益寻优。高价位本身不是风险，风险来自相对位置和路径。

### 6.3 可研究阶段规则

#### 早期触发

- 20 日涨幅不低于 3% 且不高于 25%；
- RPS20 进入前 30%，但近 5 日 RPS 改善明显；
- 突破前高或平台上沿，金额相对前 20 日 ≥ 1.2；
- 位置状态不是 `EXTENDED/CLIMAX`；
- 至少一个所属板块为 `EMERGING/CONFIRMING/ACCELERATING`，或存在新鲜在线题材事件。

#### 首次健康回撤

- 此前 20 日存在有效趋势；
- 从近期高点回撤 4%–12%；
- 收盘位于 MA10/MA20 附近，未有效跌破 MA20；
- 回撤期金额低于上涨期金额；
- 板块未退潮，强势成员留存仍有效。

#### 再加速

- 先有已确认的回撤或盘整状态；
- 当前重新站上 MA5/短平台；
- 当日或 2 日金额恢复，但不达到高潮阈值；
- RPS5 改善、板块宽度同步回升；
- 不允许仅凭当日大涨直接判再加速。

### 6.4 五类结构的角色调整

五类结构保留，但从“最终队列”降为“形态证据”：

- 稳健趋势：说明趋势质量；不能绕过位置风险。
- 强势回撤：必须区分第一次健康回撤与高位反复震荡。
- 突破准备：只有靠近触发且量价收敛才进入研究池。
- 板块龙头：说明相对角色；板块退潮时不进入优先池。
- 早期启动：与在线事件和新鲜度结合，优先级最高但需要基本流动性门。

多个结构命中只增加证据完整度，不简单累加分数。

### 6.5 个股研究排序

```text
stock_actionability =
  0.25 × stage_freshness
+ 0.20 × sector_alignment
+ 0.15 × trigger_quality
+ 0.15 × structure_quality
+ 0.10 × amount_confirmation
+ 0.10 × relative_strength_acceleration
+ 0.05 × liquidity_quality
```

绝对累计涨幅不作为正向分量。位置风险、板块退潮、数据质量和流动性为前置门。

### 6.6 优先研究池硬预算

页面只提供三个有限集合：

| 集合 | 最大数量 | 用途 |
|---|---:|---|
| 今日重点 | 20 | 默认首页和每日首先查看 |
| 次级观察 | 30 | 条件接近、等待确认 |
| 风险观察 | 20 | 历史强但过热、分歧或退潮，用于避免误判 |

“优先研究”总数最多 50，其中默认只展示今日重点 20。后台可以保留完整候选用于审计，但不得把 1,187 只直接暴露为优先清单。

今日重点内部设配额避免单一形态占满：早期触发 5、首次回撤 5、再加速 5、趋势确认 3、在线事件与本地共振 2。股票可竞争多个配额，但最终按代码去重；空缺按阶段优先级补位，不从 `EXTENDED/CLIMAX` 补位。

## 7. 在线功能线

### 7.1 情绪速览

- 同花顺涨停池读取封板、炸板、跌停及今日/昨日比率。
- 选股通读取强势、涨停、炸板、昨日涨停、跌停、新股、次新股事件池。
- 本地数据补充上涨/下跌/平盘、总成交额、MA 覆盖、创新高数量。
- 页面同时显示“在线事件时间”和“本地数据截止日”；日期不一致禁止融合。

### 7.2 涨停简图

按板位降序、同板位末封时间升序，再按封单金额降序。展示价格、涨幅、成交额、换手、流通市值、封单、首封、末封、开板、涨停类型和来源题材。成交额从同日本地行情批量补齐，不拿流通市值替代。

### 7.3 涨停分布

选股通题材 ID 与股票 `plates[].id` 做多对多 join。同一股票可属于多个题材；题材统计允许重复，市场总数按证券去重。主接口只返回题材摘要与每题材前 5 只，完整成员单独分页。

### 7.4 最强题材

在线事件强度与本地板块阶段融合。优先显示 `EMERGING/CONFIRMING/FIRST_PULLBACK/REACCELERATING`，而不是只按涨停数或 20 日涨幅。无法映射本地板块的题材保留在“事件题材”，不伪造本地连续性。

### 7.5 人气热榜

完整支持同花顺 1H/24H 人气、1H/24H 飙升、热门概念、热门行业、热门话题，并与东方财富热榜并列。平台名次不被本地数据重排；本地只补价格、成交额、阶段、位置风险、五类结构和强势关联板块。

热榜严格请求级使用，不持久化原始载荷、行、批次或历史快照。

### 7.6 板块精选

候选取在线事件题材、热门概念/行业、本地有效阶段板块的并集。综合评分只在映射和覆盖合格时计算；板块退潮/过热为硬分组，不允许高 RPS 抵消。

## 8. 板块—个股联动重做

### 8.1 交互原则

删除默认页面中的“手输板块 ID＋手输股票 ID＋选择模式”。联动从用户已经看到的对象自然进入：

- 点击板块 → 板块研究抽屉；
- 点击股票 → 个股研究抽屉；
- 顶部统一搜索支持名称和代码自动完成；
- 多板块交集是板块详情中的高级工具，不占主页面。

### 8.2 股票抽屉

按照用户实际问题排序：

1. **当前阶段**：早期触发、首次回撤、再加速、过热等。
2. **为什么进入/未进入重点**：最多 3 条决定性理由和 2 条风险。
3. **当前驱动板块**：在线事件题材、本地共同强势板块、备选板块。
4. **普通属性**：行业、概念、地区等静态归属，默认折叠。
5. **量价位置**：价格、涨幅、成交额、MA、RPS、距高点、位置风险。
6. **历史与证据**：按需加载，不在首次打开时请求。

驱动板块排序优先级：当日事件共同出现 → 板块处于有效阶段 → 剔除该股后板块仍强 → 股票在板块内角色 → 新鲜度。行业核心归属不能自动冒充驱动原因。

### 8.3 板块抽屉

1. 当前阶段及今天是否转弱；
2. 在线事件摘要和本地趋势摘要；
3. 成员按角色分组：事件龙头、早期触发、首次回撤、再加速、健康趋势、过热风险；
4. 每组最多显示 10 只，继续查看分页；
5. 显示成员留存、进入、退出和代表股更替；
6. 五类结构作为筛选标签，不覆盖板块内统一研究排序。

### 8.4 联动 API

- `GET /api/v3/research/stocks/{security_id}`：股票抽屉首屏。
- `GET /api/v3/research/stocks/{security_id}/evidence?section=`：按区块加载证据。
- `GET /api/v3/research/sectors/{sector_id}`：板块抽屉首屏。
- `GET /api/v3/research/sectors/{sector_id}/members?role=&page=`：成员分页。
- `GET /api/v3/search/suggest?q=&types=stock,sector`：自动完成。
- `POST /api/v3/research/sector-set`：2–4 板块交集/并集高级工具。

## 9. 页面重构

### 9.1 主导航

控制为五项：首页、情绪与涨停、板块研究、个股研究、热度观察。数据管理和运维放设置入口，不占研究主导航。

### 9.2 首页渐进式结构

```text
市场概况
  今日情绪、涨停/炸板/跌停、成交额、在线状态
        ↓
当前值得研究的板块
  萌芽 / 确认 / 首次回撤 / 再加速（最多20）
        ↓
板块梯队
  当前有效 / 过热风险 / 退潮（明确分开）
        ↓
今日重点个股
  最多20只，按阶段分组
```

首页不再出现泛化的“强势板块”和“核心标的”称呼。建议改为“当前有效板块”“今日重点研究”“强势但过热”“正在退潮”。

### 9.3 个股研究页

默认只显示 20 只今日重点。顶部切换今日重点、次级观察、风险观察；完整候选池放入“审计查询”，必须主动进入，且不叫优先研究。

表格核心列限制在：阶段、代码/名称、价格、当日涨幅、成交额、所属驱动板块、位置风险、触发依据。MA/RPS 等详细指标进入抽屉，避免主表再次横向爆炸。

### 9.4 板块研究页

按阶段分组卡片优先，周期矩阵作为二级深度工具。默认卡片最多 20；过热和退潮单独标签，绝不混入当前有效列表。

## 10. 数据模型改造

### 10.1 新增小型结果表

| 表 | 主键 | 规模与作用 |
|---|---|---|
| `sector_phase_daily` | `slice_id, sector_id` | 每板块每日一行，存阶段、强度、风险、谓词 |
| `stock_phase_daily` | `slice_id, security_id` | 每股票每日一行，可由共享基础因子增量生成 |

| `market_emotion_daily` | `trade_date, basis` | 每日在线/本地各一行 |
| `limit_event_daily` | `trade_date, security_id` | 只存事件股票 |
| `topic_event_daily` | `trade_date, source_id, topic_id` | 只存活跃题材 |
| `topic_event_members` | `trade_date, source_id, topic_id, security_id` | 活跃题材成员多对多 |
| `source_sector_map` | `source_id, source_sector_id, version` | 在线题材到本地板块映射 |

### 10.2 不再新增的重复物化

- 不为首页另建全市场股票副本；
- 不为每个队列复制完整技术字段；
- 不为每个快照重复相同输入哈希的全量切片；
- 不持久化热榜；
- 不把每个页面 DTO 存成数据库表。

### 10.3 计算策略

1. 全市场 OHLCV 基础因子每天增量计算一次。
2. 板块聚合共享同一成员—行情中间结果，不为周期、主线、精选分别扫描。
3. 阶段分类只读取已生成基础因子和在线事件，不重复读原始全历史。
4. 研究清单在所有阶段结果上做 top-K，写入几十行。
5. 页面只读研究清单；用户下钻某股票/板块时再按 ID 批量查询详情。

## 12. 实施阶段与小任务

### D0：冻结问题与基线

1. 封存当前发布、页面、算法合同、最新输出数量和性能。
2. 建立 `LOCAL-ALGORITHM-PRODUCT-AUDIT-01` 与 `STORAGE-EXPLOSION-AUDIT-01` 两个独立审计项。
3. 给“强势板块、核心标的、优先研究”建立旧语义弃用清单。
4. 输出 20 个明显高位股票、10 个今日转弱板块作为人工回归样例。

通过：问题样例能在旧页面复现；下一阶段 D1。

### D1：共享数据与在线基础

1. 完成在线来源合同、请求客户端、时间语义、A 股映射、失败降级。
2. 建立共享本地因子视图，确认位置、均线、RPS、金额、板块留存字段可用。
3. 定义事件稀疏表和阶段结果小表迁移。
4. 加入新任务预计行数/字节数门，不清理旧库。

通过：在线失败不阻塞本地；新增功能无全市场重复副本；下一阶段 D2。

### D2：板块阶段 V3

1. 实现退潮否决、过热、高位分歧。
2. 实现萌芽、确认、加速、健康趋势、首次回撤、再加速。
3. 实现风险优先冲突顺序。
4. 为每个阶段返回谓词、缺失、来源和转换原因。
5. 用至少 60 个交易日做状态转移审计，不以未来收益调参。

通过：人工转弱板块不再进入当前有效；历史强但高位者进入风险组；下一阶段 D3。

### D3：个股阶段与位置风险 V3

1. 建立统一位置状态。
2. 实现延伸过度、高潮、派发和破坏否决。
3. 实现早期触发、首次健康回撤、再加速和趋势确认。
4. 把五类结构改为证据输入。
5. 审计高价、科创/创业板不同涨跌幅和复权边界。

通过：连续大涨高位股不再占优先池；下一阶段 D4。

### D4：研究清单收敛

1. 实现板块 top-K 与阶段配额。
2. 实现个股今日重点 20、次级 30、风险 20。
3. 多队列、多板块、多事件按证券去重。
4. 输出入选理由、落选门和候补次序。
5. 保留完整候选审计查询，不在主页面暴露。

通过：首页板块 ≤20、今日重点个股 ≤20、优先研究总计 ≤50；下一阶段 D5。

### D5：在线事件模块

1. 情绪速览；2. 涨停简图；3. 涨停分布；4. 最强题材；5. 四类人气榜；6. 板块/话题热榜。
2. 在线题材映射本地板块。
3. 给在线事件成员批量补本地阶段和位置风险。
4. 交易日不一致、空响应、字段漂移全部 fail closed。

通过：与来源页面三日抽样一致；热榜零持久化；下一阶段 D6。

### D6：板块精选融合

1. 合并在线事件候选与本地有效阶段候选。
2. 实现透明分量评分和缺失覆盖门。
3. 分开事件强势、趋势强势、首次回撤、再加速、过热和退潮。
4. 生成代表股角色。

通过：综合结果不被 20 日累计涨幅单项支配；下一阶段 D7。

### D7：联动重做

1. 实现统一搜索和自动完成。
2. 股票/板块点击直接打开研究抽屉。
3. 重排证据顺序，隐藏内部 ID 和开发语义。
4. 成员按研究角色分组，完整表分页。
5. 多板块集合移入高级工具。

通过：用户无需输入 ID；任一首页对象一次点击见主要证据；下一阶段 D8。

### D8：首页和导航重构

1. 首页四段渐进式布局。
2. 五主导航与二级页整理。
3. 删除泛化“核心”“强势”“优先”文案。
4. 接入按需请求、取消、骨架、错误和空状态。
5. 1080p/1440p 响应式检查。

通过：首页首屏 ≤200 KiB、DOM ≤500、默认只见 20 个重点对象；下一阶段 D9。

### D9：联合验收

1. 源码审计：合同、算法、来源和排序无重复实现。
2. 数据审计：A 股范围、日期、NULL、唯一键、无未来数据。
3. 算法审计：高位否决、退潮否决、阶段冲突、top-K 配额。
4. UI 审计：导航、搜索、抽屉、弹窗、分页、慢网和失败降级。
5. 性能审计：首页、详情、并发刷新、数据库新增规模。
6. 业务对照：连续 5 日人工复核板块和个股清单。

通过：所有合同回执 `PASS`，才能替换现有正式入口。

## 13. 关键验收案例

1. 板块 RPS20 为 99%，但今日跌幅、上涨宽度和成员留存同时恶化：必须进入退潮/分歧，不得列当前有效。
2. 股票 20 日涨 40%、距 20 日高点 1%、明显偏离 MA20：即使五类结构多命中，也不得进入今日重点。
3. 股票累计涨幅一般，但首次放量突破、板块刚萌芽、位置不过热：应优先于历史涨幅最大的股票。
4. 股票首次缩量回撤至 MA10/20，板块仍确认：进入首次回撤；第二、第三次高位震荡不能冒充首次回撤。
5. 最新完整候选仍可有 1,000 只以上，但今日重点必须不超过 20，且每只有明确入选理由。
6. 某研究阶段不足配额时可由其他有效阶段补位，但不得由过热或退潮对象补位。
7. 在线题材与本地板块无法可靠映射：事件事实可见，综合分不可用。
8. 平台热榜第 1 名保持第 1，不因本地阶段差而被重排；只显示风险标签。
9. 点击股票直接显示阶段、理由、驱动板块和风险，不需要输入股票或板块 ID。
10. 页面刷新不产生新的分析切片，不写热榜，不启动全市场计算。

## 14. 数据库膨胀后续专项

功能目标版本稳定后，单独执行：

1. 按 `input_hash + dependency_hash + contract_id + trade_date` 找重复切片；
2. 建立成功发布、任务和 lease 的完整引用图；
3. 区分逻辑重复、历史修订和真正孤儿；
4. 先生成可恢复清理计划，再隔离，再验证，再删除；
5. 将高容量成员明细按日期/域写 Parquet，DuckDB 保留索引和聚合；
6. 建立每日新增行数、数据库大小和重复率告警。

该专项不能阻塞目标版本的产品重做，但 D1 必须先阻止新功能继续制造全市场重复数据。

## 15. 最终完成定义

工作台达到目标版本，必须满足：

- 首页不会把明显转弱板块称为当前强势；
- 历史涨幅最大、位置过高的股票不会自动成为核心研究对象；
- 今日重点股票最多 20，只展示真正值得继续研究的少量对象；
- 板块和个股都有生命周期、位置风险和明确转换原因；
- 在线最强题材、涨停分布、涨停简图、情绪速览、热榜与本地研究能力完整融合；
- 联动无需输入内部 ID，点击对象即可看到驱动、阶段、角色和风险；
- 首页与详情按需请求，不加载全量 DOM；
- 新功能的数据增长与事件/短名单规模同阶，不再与全市场 × 板块 × 窗口相乘；
- 所有结论可追溯到在线来源或本地版本化合同，不使用含义不明的“综合强势”。

## 16. 方案审计结论

本文已经补齐上一份在线方案缺失的本地算法和产品层：板块退潮、高位过热、个股位置、生命周期、优先池硬预算、五类结构角色调整、联动交互和计算存储策略均进入实施主线。

依赖顺序已重新校正：必须先冻结语义和共享数据，再做板块阶段，再做个股阶段和清单收敛，之后融合在线事件，最后重做联动与首页。若跳过 D2–D4 直接做在线页面，工作台仍会把更多数据塞进错误的“强势/核心”框架；若先改 UI 再改算法，只会得到更漂亮但仍然无用的页面。

仍需在实施 D0–D3 用真实历史样本冻结的内容包括位置阈值、阶段分位参数和不同板块类型的波动适配。冻结方法必须基于状态稳定性、解释一致性和人工复核，不允许按未来涨幅最大化调参。
