## 3. 新增升级点的具体意义

1. 重点清单的“容量限制”与“资格标准”分开：最多20不等于每天一定20。每次新增/移出给理由，避免少量列表只是截断原1187只。
2. 稳健上涨股票不因涨幅高直接消失。涨停榜保留客观高板；研究清单显示位置风险，用户能区分“领涨事实”和“当前关注”。
3. 本地昨日分析与在线今日行情可以正常同屏使用。日期不同的值不能混算，但可以明确作为背景。这是盘中功能能用的前提。
4. 原始板块无价格指数时不伪造POS/回撤。先用已有成员宽度和共同成员量额建立阶段，后续有可靠指数再加价格阶段。
5. 原有五类结构、RPS、新高、矩阵继续作为正常研究工具。无需把熟悉功能全收进“审计查询”；只有完整无收敛候选不再占首页。
6. 状态与数据身份小表复用现有平台；避免为了每个模块重新造注册中心、数据库或前端。
7. 最早一阶段就处理网络阻塞和点击联动，用户不用等全部算法实现才发现页面仍难用。
8. 补全事件批次集合的实际载体、盘中内存容量/过期行为及迁移归属，避免接口写了bundle却没有实现载体。仅事件允许该缓存，热榜维持请求时读取、不持久化。

## 4. 关于参数和能力承诺的收紧

Sol中25%、15%、97.5%、5/5/5等数字并无本次实证支撑。Astra保留必要工程初值，并在主方案明确标PREVIEW；算法样例、参数敏感性、阶段稳定性内部审计后才能升级版本。主方案没有承诺“这个信号更容易上涨”，也没有把“高位派发”写成日线可以识别的事实。

没有已知历史成员时，用当前成员重建只能说明按当前归属回看。5日分析历史不能直接做250日滚动分位；已有原始日线可补所需输入，但不要求重建全部历史数据库。不能再让缺失长历史把首版页面一直卡在“观察中”。

## 5. 保留、替代与实施入口

保留：项目联网、TDX研究背景、在线六类功能、20/30/20默认容量、A股范围、五类结构、来源可查、按需加载。
替代：任意加权总分、固定阶段配额、接近新高即否决、无记忆的首次回撤、日线推断派发、盘中强求同日背景、在线日表覆盖写、UI最后交付。
暂缓：长历史高分位与ATR增强、旧库清理、复杂恢复和灾备。暂缓不影响公开事件和基础研究版可用。
