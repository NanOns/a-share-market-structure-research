# 结构研究工作台 M7–M15 详细升级方案

> 2026-09-09更新：本文v1.1仅保留作历史对照，实施以[M7–M15完整实施方案v2.1](WORKBENCH_M7_M15_IMPLEMENTATION_PLAN_V2_1.md)为准。2.1已合并审计修正和完整接口/数据库/UI/验收细节，无需与本文拼接。本文的北交所排除、历史复制和过强PASS结论不再适用。后续见[工作台后续发展计划](WORKBENCH_POST_M15_ROADMAP.md)。

版本：`workbench-upgrade-plan-v1.1`  
依据：当前 M0–M6 代码、DuckDB 数据库、通达信本地数据，以及《龙字诀 v2.1.2 功能审计与工作台采纳方案（最终取舍版）》  
性质：实施设计与验收合同草案，不是交易策略，不包含概率预测或自动交易。

## 1. 目标与边界

### 1.1 总目标

将当前以“当日板块排行＋五类结构队列”为主的工作台升级为具有时间维度的研究系统：先建立可复现的历史派生数据，再实现板块周期、主线周期、创新高/RPS、市场周期、交叉选股、个股研究透视和收盘涨停梯队；最后按需要接入经过验证的免费在线数据。

### 1.2 已确认实施范围

1. 首页渐进式视图：市场概况 → 强势板块 → 板块梯队 → 代表个股。
2. 板块周期矩阵：5/10/20/30日强度、排名、宽度、成交额和成员变化。
3. 板块成员留存、扩散/收缩和龙头更替。
4. 版本化主线周期分类。
5. 当前板块—个股联动加强和2～4板块交叉选股。
6. 只读板块属性库。
7. 20/30/60/100日创新高、连续创新高、板块创新高宽度和趋势曲线。
8. 市场情绪历史。
9. 成交额、换手率、异常放量和MA均线组合分析。
10. 个股研究透视，借鉴天眼模式的统一聚合交互。
11. 收盘涨停梯队；暂不要求精确盘中炸板时间。
12. A/B级在线热榜和涨停原因的数据源验证与可选接入。

### 1.3 暂不实施

- 投资日历和未来事件驱动分析。
- 每日研究导出包。
- 登录、会员、积分、版本更新。
- 外部终端跳转和自动下单。
- 精确盘中炸板时间。
- C级动态签名/Cookie绕过接口和D级私有会员接口。

### 1.4 必须先解决的基线问题

当前底层 `adjusted_daily.parquet` 有约1,962万行，适合历史计算；但正式数据库只有3个交易日的发布头。周期页面若直接从当前 `sector_daily` 查询，只能得到3天数据。另一个问题是现有板块成员合同为 `CURRENT_TDX_MEMBERSHIP`，标记 `pit_membership=false`、`historical_backtest_safe=false`，不能把今天的成员关系伪装成过去真实成员。

因此所有周期功能必须区分：

- `AS_OBSERVED`：当日真实采集并封存的成员快照，可用于严格跨日比较。
- `CURRENT_MEMBERSHIP_REPLAY`：使用当前成员回算历史，只能用于研究浏览，页面必须显示“当前成员回算”，不得用于历史回测结论。

默认股票范围同时固化为 `CN_A_CORE_V1`：仅展示沪深主板、创业板和科创板正常上市 A 股；永久排除沪市 900 开头、深市 200 开头的 B 股，排除新三板、退市整理及已退市证券。北交所虽然属于 A 股市场，但为避免现有 `BJ.*` 数据质量和板块映射问题，首版不进入默认范围；后续可在独立开关中启用 `CN_A_ALL`，不能静默混入。

## 2. 依赖顺序

```text
M7 历史基础、A股范围与数据合同
 ├─ M8 市场/个股技术状态（MA、成交、换手、放量、新高、涨停）
 │   ├─ M9 板块周期矩阵与成员状态
 │   │   ├─ M10 主线周期分类
 │   │   ├─ M11 板块属性库、交叉选股与联动增强
 │   │   └─ M12 个股研究透视
 │   ├─ M13 市场周期与收盘涨停梯队
 │   └─ M12 个股研究透视
 ├─ M14 A级/B级在线数据源适配
 │   ├─ M12 在线证据增强
 │   └─ M13 在线热榜增强
 └─ M15 整体界面整合、性能与最终验收
```

依赖原则：

- 先有历史事实表，再做跨日分类。
- 先有板块周期矩阵，再判断主线。
- 先有属性库和成员状态，再做交叉选股。
- 个股透视只聚合已有模块结果，不重复计算一套指标。
- 在线数据是增强层，不能成为基础页面启动条件。

## 3. 总体界面信息架构

### 3.1 一级导航

保持一级导航不超过6项，避免页签继续横向膨胀：

1. **研究总览**
2. **板块研究**
3. **个股研究**
4. **联动选股**
5. **市场周期**
6. **数据说明**

### 3.2 二级页面

| 一级导航 | 二级页面 |
|---|---|
| 研究总览 | 今日总览 |
| 板块研究 | 板块排行、周期矩阵、主线周期 |
| 个股研究 | 优先研究、五类结构、创新高/RPS、个股透视 |
| 联动选股 | 板块个股联动、交叉筛选、板块属性库 |
| 市场周期 | 市场情绪、涨停梯队、平台热榜（可选） |
| 数据说明 | 数据源状态、字段解释、合同与身份 |

### 3.3 布局规则

- 一级导航固定在内容顶部；二级导航使用分段按钮，不再增加新的一级页签。
- 页面默认只加载首屏所需接口；切换二级页时再加载。
- 表格每页最多100行；周期矩阵默认20个板块×10天，用户操作后再扩展。
- 详情统一使用右侧抽屉；结构证据继续使用弹窗。抽屉适合跨模块长内容，弹窗适合单一证据。
- 颜色只表达涨跌、状态和数据质量，不用过多渐变。
- 所有数字字段有表头说明或悬停解释；金额统一使用万、亿、万亿。
- 宽表允许容器内横向滚动，但页面主体不得出现全局横向滚动。
- 手机/窄屏不是首要目标；宽度小于1000px时左右布局折叠为上下布局。

### 3.4 前端取数合同

- HTML只保留页面骨架、组件模板和必要字典，不嵌入全市场、全板块或全历史 JSON。
- 列表筛选、排序、搜索和分页全部由接口执行；前端不得先取全量数据再操作 DOM。
- 所有列表响应统一为 `publication_id`、`analysis_snapshot_id`、`page`、`page_size`、`total`、`items`、`data_quality`。
- 所有数据请求必须显式携带成功 `publication_id`；`page_size` 限制为1～100，排序字段使用后端白名单，禁止把用户输入拼接进SQL。
- 图表接口只返回请求日期窗口的聚合点；明细在点击单元格、日期或股票后延迟加载。
- 日期或筛选变化时递增 request epoch，并取消或忽略旧请求，避免迟到响应覆盖新页面。
- 首屏只并行请求可见卡片；隐藏二级页、抽屉历史图和在线增强不得预加载。
- 金额由接口返回原始“元”数值，前端只用一个公共格式化器显示：`16.2亿`、`80.9亿`，禁止 `1.62十亿`、`0.081百亿` 等混合单位。
- NULL必须显示“暂无/数据不足”，不能转成0、空白或NaN。
- 缺少发布返回404，无对应成功分析快照返回409，参数错误返回400；可选在线源不可用只在增强接口返回可解释状态，不拖垮本地接口。

## 4. 数据库总体改造

现有发布表保持不变。新增表采用版本化、可追溯设计；高频筛选字段使用实体列，详细证据放 `payload_json`。

历史派生层不能把每个历史交易日伪造成一次正式发布。正确模型是：一次成功发布绑定一个不可变 `analysis_snapshot_id`，该快照包含“截至这次发布日”可见的全部历史派生行。API仍以 `publication_id` 为入口，后端先解析其绑定的分析快照；同一响应不得跨快照混读。

### 4.1 新增分析快照身份表

#### `analysis_snapshots`

- `analysis_snapshot_id VARCHAR` 主键。
- `anchor_publication_id VARCHAR`，引用成功的 `publications.publication_id`。
- `as_of_trade_date DATE`，快照允许读取的最晚日期。
- `derivation_contract_version VARCHAR`。
- `universe_contract_version VARCHAR`，首版为 `CN_A_CORE_V1`。
- `membership_basis VARCHAR`：`AS_OBSERVED` 或 `CURRENT_MEMBERSHIP_REPLAY`。
- `source_identity_sha256 VARCHAR`、`computation_identity_sha256 VARCHAR`。
- `status VARCHAR`：`STAGING`、`SUCCESS`、`FAILED`。
- `created_at_utc TIMESTAMP`、`payload_json JSON`。
- 唯一键：`anchor_publication_id, derivation_contract_version, membership_basis`。

#### `publication_analysis_snapshots`

- `publication_id VARCHAR`，引用 `publications`。
- `analysis_domain VARCHAR`：`LOCAL_CORE`、`ONLINE_ENHANCEMENT` 等。
- `analysis_snapshot_id VARCHAR`，引用 `analysis_snapshots`。
- 主键：`publication_id, analysis_domain`。

绑定只能在发布事务中写入；成功发布之后不得把指针改到另一个分析快照。补算或算法升级必须生成新快照，并通过新发布修订版启用。

### 4.2 新增数据源与抓取审计表

#### `data_sources`

- `source_id` 主键，例如 `TDX_LOCAL`、`EASTMONEY_HOT_RANK`。
- `source_class`：`LOCAL`、`ONLINE_A`、`ONLINE_B`。
- `display_name`。
- `adapter_version`。
- `terms_status`：`VERIFIED`、`PERSONAL_RESEARCH_ONLY`、`REJECTED`、`UNKNOWN`。
- `enabled`。
- `payload_json`。

#### `ingestion_runs`

- `ingestion_id` 主键。
- `source_id`。
- `requested_at_utc`、`finished_at_utc`。
- `target_trade_date`。
- `status`：`SUCCESS`、`DEGRADED`、`FAILED`。
- `http_status`、`row_count`、`raw_sha256`、`error_code`。
- `payload_json`。

#### `online_snapshots`

- `snapshot_id` 主键。
- `source_id`、`trade_date`、`dataset_name`。
- `observed_at_utc`。
- `adapter_version`、`raw_sha256`。
- `payload_json`。
- 唯一键：`source_id, trade_date, dataset_name, raw_sha256`。

### 4.3 新增历史分析表

#### `stock_technical_daily`

主键：`analysis_snapshot_id, trade_date, security_id`。

实体字段：

- `analysis_snapshot_id`
- `trade_date`
- `latest_price`
- `ret1`
- `turnover_amount`
- `turnover_rate`、`turnover_rate_basis`
- `ma5`、`ma10`、`ma20`、`ma60`
- `above_ma5/10/20/60`
- `ma_alignment`
- `amount_ratio_1_20`
- `amount_ratio_5_20`
- `abnormal_volume_class`
- `new_high_20/30/60/100`
- `new_high_streak`
- `limit_state`
- `limit_streak`
- `payload_json`

换手率若本地没有可靠流通股本，必须为NULL并标记依据不足；不能用成交量随意代替。

#### `market_cycle_daily`

主键：`analysis_snapshot_id, trade_date`。

字段：上涨、下跌、平盘、涨停、跌停、成交额、MA20/MA60上方比例、20/30/60/100日创新高数量、五类队列数量、强势板块数量、数据覆盖率和 `payload_json`。

#### `sector_cycle_daily`

主键：`analysis_snapshot_id, trade_date, sector_id`。

字段：

- 当日和5/10/20/30日排名
- 排名变化
- 5/20日强度及变化
- 板块自身当日涨幅 `sector_ret1` 与来源
- 成员当日涨幅中位数 `member_ret1_median`（仅作分布统计）
- 上涨宽度及变化
- 成交额及5/20日均额比
- 有效成员总数和数据覆盖率
- 强势成员数
- 新增强势成员、退出强势成员
- 成员留存率
- 龙头代码、龙头名次、龙头连续天数
- 是否更换龙头
- 创新高成员数及宽度
- 成员口径和合同版本

#### `sector_member_state_daily`

主键：`analysis_snapshot_id, trade_date, sector_id, security_id`。

字段：板块内名次、相对强度百分位、是否强势成员、是否新增、是否留存、是否退出（退出可记录在变化表）、五类结构命中、新高状态和 `payload_json`。

#### `stock_sector_associations_daily`

主键：`analysis_snapshot_id, trade_date, security_id, sector_id`。

字段：板块语义类型、是否允许作为强势关联、板块强度百分位、股票板块内名次/总数/百分位、5日同向天数、板块成员留存率、关联层级、顺序位置、证据原因码和 `payload_json`。这是“当前强势关联板块”的唯一后端结果，前端不得自己从所属板块列表挑选。

#### `sector_membership_changes`

主键：`analysis_snapshot_id, trade_date, sector_id, security_id, change_type, basis_version`。

记录 `ADDED`、`REMOVED`，并标记比较的前后快照。只有两个真实 `AS_OBSERVED` 快照才能称为真实成员变化；回算口径只显示计算集合差异。

#### `mainline_daily`

主键：`analysis_snapshot_id, trade_date, sector_id`。

字段：`mainline_class`、连续上榜天数、5/10/20/30日上榜次数、排名趋势、宽度趋势、成交额趋势、成员留存、龙头稳定度、失败条件和合同版本。

#### `limit_ladder_daily`

主键：`analysis_snapshot_id, trade_date, security_id`。

字段：`limit_state`、`limit_streak`、`previous_limit_streak`、`promotion_state`、`ladder_level`、关联板块、成交额、换手率、五类结构命中和证据。

#### `stock_external_evidence`

主键：`source_id, trade_date, security_id, evidence_type, evidence_hash`。

用于在线涨停原因、平台热榜、龙虎榜等。包含标题、摘要、排名、来源时间、抓取时间和原始快照引用。它永远不覆盖本地技术字段。

### 4.5 迁移、写入和保留策略

1. 新增独立 schema migration，不直接修改旧表主键或回填旧发布行。
2. 历史计算先写带随机临时名的 staging 表；校验日期上限、唯一键、行数、范围合同和哈希后，在一个 DuckDB 事务中写入 `analysis_snapshots`、派生表、发布绑定。
3. `analysis_snapshot_id` 由锚定发布、合同版本、成员口径和计算身份确定性生成；相同输入重试命中同一身份。
4. API请求必须带成功 `publication_id`，再解析 `LOCAL_CORE` 快照；响应回显 `publication_id`、`analysis_snapshot_id`、`as_of_trade_date`、`membership_basis` 和合同版本。
5. 当前发布及最近两个成功修订版的快照永久保留；更旧未被任何发布引用的快照才允许进入清理候选，清理由现有 `cleanup_jobs` 审计执行。
6. 在线原始快照单独保存，不写入 `LOCAL_CORE` 派生表；页面聚合时按证券、交易日和来源时间关联。

### 4.6 物理字段与单位合同

- 证券、板块、快照和版本标识使用 `VARCHAR`；交易日使用 `DATE`；抓取时间使用 UTC `TIMESTAMP`。
- 价格使用 `DECIMAL(18,4)`，金额使用以元为基准的 `DECIMAL(24,2)`；数据库中不保存“亿”“万亿”等格式化字符串。
- 收益率、宽度、留存率、百分位和比值使用 `DOUBLE`，统一保存为小数比例，例如 `0.05` 表示 `5.0%`。
- 数量和名次使用 `BIGINT`，状态开关使用 `BOOLEAN`，枚举使用受合同约束的 `VARCHAR`。
- API同时返回原始数值与单位元数据，显示层统一格式化；禁止同一字段有的接口返回 `5`、有的接口返回 `0.05`。
- 数据不足使用NULL并附 `quality_code`；不得以0代替未知值。

## 8. M10：主线周期

### 8.1 输入依赖

只读取M9的板块周期结果和M8的市场状态，不直接扫描原始日线。在线热榜和原因首版不参与分类。

### 8.2 分类维度

- 5/10/20/30日进入同类前20%的次数。
- 当前连续上榜天数。
- 排名斜率和最近3日排名变化。
- 上涨宽度水平及变化。
- 成交额扩张及连续性。
- 强势成员留存率。
- 龙头稳定度。
- 创新高成员宽度。
- 数据覆盖率。

### 8.3 第一版分类

- `NEW_MAINLINE`：近期首次满足强度、宽度和成交扩张。
- `SUSTAINED_MAINLINE`：连续上榜且成员留存稳定。
- `REACCELERATING_MAINLINE`：中期仍强，短期排名、宽度和成交额重新改善。
- `BROADENING`：强势成员增加、宽度扩散，但持续性尚不足。
- `HIGH_LEVEL_CONTRACTION`：排名仍高，但宽度和成员留存下降。
- `FADING`：排名、宽度和成交额共同转弱。
- `INSUFFICIENT_HISTORY`：历史或成员口径不足。

所有分类使用硬条件表，并保存命中/失败条件。不得使用隐藏综合分决定类别。

`MAINLINE_V1` 的首版可执行门槛和判定优先级如下；所有百分位按同类板块截面计算，任一关键字段NULL时降级为 `INSUFFICIENT_HISTORY`，不能跳过条件：

1. `INSUFFICIENT_HISTORY`：有效历史少于10日、当日成员覆盖率低于80%，或成员口径不可识别。
2. `REACCELERATING_MAINLINE`：20日进入前20%不少于6次；今日强度百分位不低于80%；较3日前排名至少改善10个百分位；上涨宽度较3日前提高至少10个百分点；成交额/20日均额不低于1.2。
3. `SUSTAINED_MAINLINE`：最近5日进入前20%不少于3次且当前连续上榜不少于2日；上涨宽度不低于50%；强势成员留存率不低于60%；龙头未确认更替或新龙头已连续2日确认。
4. `NEW_MAINLINE`：今日进入前20%，此前5日进入前20%不超过1次；上涨宽度不低于55%；成交额/20日均额不低于1.1；强势成员进入数大于退出数。
5. `HIGH_LEVEL_CONTRACTION`：今日强度仍在前20%，但上涨宽度较3日前下降至少10个百分点，或强势成员留存率低于50%。
6. `BROADENING`：今日强度百分位不低于70%；进入强势成员数大于退出数；上涨宽度较前日提高至少10个百分点；且不满足前三种主线状态。
7. `FADING`：今日强度百分位低于60%，最近3日排名累计下降至少15个百分位，并且宽度与成交额比同时下降。

未命中上述状态时为 `OBSERVING`。优先级严格按上述顺序，避免同一板块同时落入两个类别；阈值写入合同和 `payload_json`，后续修改必须升级版本并保留旧结果。

### 8.5 页面

“板块研究/主线周期”：

- 顶部状态卡：持续主线、新晋、再加速、扩散、高位收缩、退潮数量。

- 每个分类有正例、边界例、反例。
- 修改在线数据不会改变首版本地主线类别。
- 历史不足时不会误分为退潮或新晋。
- 分类证据能用自然语言解释所有硬条件。

## 9. M11：板块属性库、交叉选股与联动增强

### 9.1 属性库

板块语义分为：

- `INDUSTRY_ATTRIBUTE`
- `THEME_ATTRIBUTE`
- `NORMAL_STYLE_ATTRIBUTE`
- `PRICE_BEHAVIOR_TAG`
- `EVENT_TAG`
- `STATUS_TAG`
- `UNKNOWN_TAG`

建立版本化名称规则，但允许人工覆盖；每个分类保存匹配规则和证据。行情标签永远不能成为当前强势关联板块。

### 9.2 集合操作

- 选择2～4个板块。
- 交集：同时属于所有选中板块。
- 并集：属于任一板块。
- 排除：从结果中排除指定板块/标签成员。
- 结果内筛选五类结构、研究带、新高窗口、MA状态和成交额状态。
- 集合运算由后端执行，页面只提交板块ID和筛选条件。

### 9.3 联动增强

现有板块—个股联动增加：

- 当前板块周期类别。
- 成员昨日/今日名次及变化。
- 强势成员状态：新增、留存、退出。
- 当前和候选龙头。
- 五类结构筛选。
- 仅看创新高、异常放量、MA多头。
- 个股反查时按“强势关联、行业、概念、正常风格、行情标签”分组。

“当前强势关联板块”使用版本化规则 `STOCK_SECTOR_ASSOC_V1` 预计算：

1. 候选范围只允许行业、概念和正常风格；近期强势、昨日首板、昨日连板、最近多板、昨日上榜等行情/状态标签直接排除。
2. 板块当日数据覆盖率必须达标，且当前同类强度百分位、5日上榜情况或扩散状态至少满足一项硬门槛；仅仅“股票属于该板块”不构成强势关联。
3. 股票必须在该板块内有有效名次，并保存“第N名/有效M只”；成员总数来自相同分析快照，不能留空或跨日期拼接。
4. 候选按可解释元组排序：板块强度百分位、股票板块内百分位、最近5日与板块同向天数、板块成员留存率、板块语义优先级、`sector_id`。阈值和方向写入合同，不使用隐藏总分。
5. 第一名标记“当前强势关联”，第二、三名标记“备选关联”；行业核心/一级板块只在“基础属性”组展示，除非它本身通过上述强势门槛。
6. 页面措辞使用“关联”而不是“上涨原因”。只有带来源的在线资讯或人工记录才允许显示为事实原因。

### 9.4 接口

- `GET /api/sector-library?publication_id=&type=&q=&page=&page_size=`
- `POST /api/sector-intersection/query`：请求体必须包含 `publication_id`；该接口是只读查询，只用POST承载结构化条件，不得保存状态。
- `GET /api/linkage/history?publication_id=&sector_id=&days=&page=&page_size=`
- `GET /api/stocks/{security_id}/memberships?publication_id=`
- `GET /api/stocks/{security_id}/sector-associations?publication_id=&days=`

### 9.5 页面

“联动选股”采用三栏但不过载：

- 左栏：板块搜索和已选板块。
- 中栏：集合条件、五类结构和技术状态筛选。
- 右栏：分页结果。
- 右侧抽屉：选中股票的板块分组和近期名次变化。
- 联动结果固定展示最新价、当日涨幅、成交额、板块内名次/成员总数；“当前强势关联”与“基础属性”分列显示。
- 窄屏折叠为选择区＋结果区。

### 9.6 验收

- 交集、并集、排除用集合样本精确验证。
- 最多4个板块，重复选择不改变结果。
- 行情标签不能进入强势关联候选。
- 默认 `CN_A_CORE_V1` 筛选结果不包含 B 股、`BJ.*`、新三板和退市证券。
- 反向查询排名与正向板块成员排名一致。
- 对每只具有正常板块且满足门槛的股票，强势关联第一名非空；没有合格板块时明确显示“暂无强势关联”，不能回退到行情标签补位。
- 关联排序在数据库输入行顺序变化后保持一致，并能逐项解释排序元组。

## 10. M12：个股研究透视（借鉴天眼模式）

### 10.1 打开方式

所有股票名称/代码统一支持点击，打开右侧抽屉；不跳转外部软件。路由状态保存 `security_id`，刷新页面后可恢复。

### 10.2 抽屉内容

#### 概览

- 代码、名称、最新价、当日涨幅、成交额。
- 当前主要结构和研究带。
- 当前强势关联板块与依据。

#### 技术状态

- MA5/10/20/60及价格相对位置。
- 均线排列。
- 成交额、5/20日均额、异常放量分类。
- 换手率及数据依据。
- 20/30/60/100日新高状态。
- 5/20/60日RS/RPS。

#### 板块环境

- 行业、概念、正常风格、行情标签分组。
- 每个正常板块的当前名次、周期类别、成员名次变化。
- 强势板块首选和最多两个备选。

#### 历史轨迹

- 最近20日价格与MA曲线。
- 成交额柱。
- RPS曲线。
- 五类结构首次/持续命中时间线。
- 所属板块强度变化。

#### 在线增强

- 平台热榜排名。
- 涨停原因或异动原因。
- 明确显示来源和抓取时间。
- 无在线数据时整个区域折叠为“暂无在线增强数据”，不影响其他内容。

### 10.3 接口

- `GET /api/stocks/{security_id}/insight?publication_id=&days=20`
- 返回聚合后的分组对象；前端不分别请求十几个接口。
- 在线内容可以异步补请求 `/api/stocks/{security_id}/external-evidence?publication_id=`，避免拖慢抽屉首屏。

### 10.4 性能

- 抽屉首屏只取概览、技术状态和板块环境。
- 历史图表在切换到对应区块时加载。
- 单股票聚合结果按 `analysis_snapshot_id+security_id` 缓存；`publication_id` 只用于解析不可变快照。
- 关闭抽屉取消未完成请求或忽略迟到响应。

### 10.5 验收

- 从任一股票表格打开结果一致。
- 首屏本地数据缓存命中目标小于500ms。
- 在线超时不阻塞本地内容。
- 所有百分比、金额、MA和新高字段有解释。
- 不出现行情标签作为强势原因。

## 11. M13：市场周期与收盘涨停梯队

### 11.1 市场周期

展示30/60/90/120/250日：

- 上涨、下跌、平盘家数。
- 涨停、跌停家数。
- 全市场成交额及5/20日均额。
- MA20、MA60上方比例。
- 20/30/60/100日创新高数量。
- 五类结构命中数量。
- 强势板块、扩散板块、收缩板块数量。

图表拆为三行：市场广度、成交与趋势覆盖、涨停/创新高/队列强度。鼠标悬停显示单日明细，不计算黑盒总温度。

### 11.2 收盘涨停梯队

- 首板、2板、3板及更高。
- 昨日涨停今日晋级。
- 昨日涨停今日未封板。
- 各梯队数量和晋级率。
- 股票关联的正常强势板块。
- 成交额、换手率、异常放量、MA状态和五类结构。
- 点击股票打开个股透视。

没有盘中明细时不展示炸板率。若将来A/B级接口提供可靠炸板池，再作为独立增强字段加入。

### 11.3 技术实现

- 市场广度只聚合 `CN_A_CORE_V1` 范围内、目标日有有效行情的 `stock_technical_daily`，同时保存有效数、停牌/缺失数和覆盖率。
- 涨停梯队使用未复权前收盘、当日收盘和日期敏感规则计算；价格比较使用最小报价单位容差，不能直接比较浮点相等。
- 连板按全市场交易日序列递推：前一市场交易日无有效行情或不是涨停时归零，不能跨停牌/缺失日续板。
- 晋级和未封板由相邻两个市场交易日的已保存状态做集合连接，前端不得凭当前列表推算。
- 市场周期曲线在分析快照生成时聚合写入，不在每次请求时扫描数千万行日线。

### 11.4 接口

- `GET /api/market/cycle?publication_id=&days=`
- `GET /api/market/day-detail?publication_id=&trade_date=`
- `GET /api/limit-ladder?publication_id=&trade_date=&level=&page=&page_size=`
- `GET /api/limit-ladder/promotion-history?publication_id=&days=`

### 11.5 页面

- “市场周期/市场情绪”顶部提供30/60/90/120/250日切换，默认60日；三组图共用日期十字线，点击日期打开当日明细抽屉。
- “市场周期/涨停梯队”顶部显示各层数量和晋级率，下方按首板、2板、3板、4板及以上分组；每组独立分页，不一次渲染全部股票。
- 股票行固定展示代码、名称、最新价、当日涨幅、成交额、正常强势关联板块和结构；换手、放量、MA放入展开列。
- 没有盘中数据时页面完全隐藏炸板率卡片，不显示0%。

### 11.6 验收

- 市场家数之和与当日有效A股范围一致。
- 涨停识别按证券规则样本复算通过。
- 连板不跨停牌日误累计，按实际交易日序列处理。
- 晋级率分母为0时显示暂无。
- 图表切换250日不向DOM创建全市场股票节点。

## 12. M14：A/B级在线数据源验证与增强

### 12.1 测试范围

M14是唯一需要联网的阶段。在项目所有者正式修改根目录 `AGENTS.md` 的“No network data”守则之前，本阶段保持未启用，不进行实际网络调用。解除该约束后也只测试：

- A级官方公开免费接口。
- B级无需绕过登录、动态签名或私有鉴权的公开网页接口。

优先对象：

1. 东方财富公开热榜/行情接口。
2. 同花顺公开热榜。
3. 可公开访问的涨停原因。
4. 龙虎榜，低优先级。

### 12.2 每个数据源的准入测试

- 使用条款和个人研究可用性记录。
- 无账号、无私有Token、无验证码绕过。
- 连续10个交易日样本的成功率。
- 字段完整率和日期一致性。
- 股票代码映射准确率。
- 请求频率与缓存策略。
- 响应结构漂移测试。
- 与本地收盘价/交易日交叉校验。
- 失败时不影响本地主流程。

### 12.3 适配器接口

统一实现：

- `probe()`：健康与字段检查。
- `fetch(trade_date)`：获取原始数据。
- `normalize(raw)`：转换统一模型。
- `validate(rows, local_context)`：日期、代码和范围校验。
- `persist(snapshot)`：保存原始哈希和标准化结果。
- `status()`：向页面报告最后成功、延迟和错误。

工作台只通过本地后端暴露：

- `GET /api/data-sources/status`
- `GET /api/hot-rankings?publication_id=&source=&page=&page_size=`
- `GET /api/stocks/{security_id}/external-evidence?publication_id=&type=`

浏览器不得直接请求第三方域名，避免跨域、凭据泄漏、重复抓取和不可审计响应。

### 12.4 热榜融合

- 同花顺和东方财富分别保存平台名、榜单类型、排名、排名变化和抓取时间。
- 同一股票在两个平台同时出现时并列显示，不合并成总热度分。
- 页面支持平台筛选和“仅看同时上榜”。
- 热榜不改变五类结构、优先研究分或主线分类。

### 12.5 涨停原因融合

- 保存原始原因、清洗原因、题材名称和来源。
- 同一股票多来源原因并列，不覆盖。
- 只展示已经发生的当日/历史原因。
- 没有A/B级稳定来源则关闭该模块。

### 12.6 页面

- “数据说明/数据源状态”按来源显示级别、启用状态、最近成功时间、目标交易日、缓存年龄、字段完整率和最近错误；错误详情进入弹窗。
- “市场周期/平台热榜”只有至少一个来源准入后才出现；顶部按东方财富、同花顺和“同时上榜”切换，列表服务端分页。
- 个股透视和主线证据只显示紧凑来源徽标；点击后弹窗展示原始标题/摘要、来源、数据时间和抓取时间。
- 过期数据必须显示“缓存数据，截至……”，禁止用旧数据冒充当日结果。
- 未准入、被禁用或失败的来源不显示空白表格，而显示明确状态及本地功能仍可用的说明。

### 12.7 验收

- 每个启用适配器有独立合同和录制样本测试。
- 测试不依赖正式接口实时可用；使用脱敏固定响应回归。
- 在线失败、超时、限流、空响应和字段漂移均有测试。
- 页面始终显示来源和更新时间。
- 禁止调用龙字诀 `loong1.com` 私有服务或复用其凭据。

## 13. M15：整体界面整合与最终验收

### 13.1 首页最终布局

首屏从上到下：

1. 日期、发布身份、数据源健康状态。
2. 市场概况卡：涨跌家数、成交额、涨停数、创新高数、强势板块数。
3. 强势板块：行业、概念各5～8个，不展示行情标签补位。
4. 板块梯队：持续主线、新晋、再加速、高位收缩。
5. 代表个股：每个板块最多3只，显示强势关联依据。
6. 优先研究个股：保留现有候选池，但字段可通过“紧凑/详细”切换。

### 13.2 复杂度控制

- 默认页面只展示结论和关键依据。
- 详细指标进入抽屉、弹窗或二级页面。
- 同一字段只保留一个中文名称。
- 默认不展示合同内部字段名。
- 在线增强用小徽标，不抢占主列。
- 空状态说明缺少什么，不显示空白表格。

### 13.3 全局性能指标

- 工作台静态HTML仍是薄壳，不嵌入市场全量数据。
- 首页冷启动目标小于3秒，热缓存小于1秒。
- 页签切换不因未访问模块预加载全量历史。
- 单接口默认响应不超过100行；图表最多返回请求窗口所需聚合点。
- 并发访问同一重计算缓存时只计算一次。
- 浏览器主线程长任务不得持续超过200ms。

### 13.4 无障碍与交互验收

- 弹窗支持X、遮罩和Esc关闭。
- 抽屉支持关闭按钮和Esc，焦点不会丢到页面后方。
- 表格按钮使用按钮样式，不使用伪链接。
- 图表数据同时有可读表格或明细。
- 所有筛选条件可以一键清空。
- 页面后退/刷新可恢复一级页、二级页和选中股票。

### 13.5 总体验收门

最终状态只能是：

- `FULL_PASS`：本地模块全部通过，启用的在线源通过准入与降级测试。
- `DEGRADED_PASS`：本地模块全部通过，部分可选在线源不可用但降级正确。
- `BLOCKED`：历史数据口径、核心派生结果或页面主流程存在错误。

在线源故障本身不能导致核心本地功能 `BLOCKED`；但如果页面把在线缺失误显示成0或正常，则必须阻断发布。

### 17.3 风险缺口

1. **历史成员真实性**：现有成员不是PIT安全。解决方式是从现在开始每日封存真实快照；旧日期回算必须标识。
2. **换手率股本**：当前已审计字段中未确认可靠流通股本。M8开始前先专项查源，缺失则保留NULL。
3. **涨跌停规则**：需要日期敏感规则和特殊证券样本，不能只按10%判断。
4. **正式发布天数少**：需要历史派生补算，但不得修改原发布事实。
5. **在线接口稳定性**：只允许A/B级；必须有录制样本、缓存和降级。
6. **页面复杂度**：通过6个一级导航、二级分段、抽屉详情和延迟加载控制。
7. **术语误导**：主线、龙头、热度和强势都必须在页面说明其计算口径，不代表未来上涨。

### 17.4 审计结论

本方案已覆盖用户确认的全部功能、六项龙字诀会员功能的借鉴落点、数据依赖、数据库表、接口、页面、性能、降级和验收。实施顺序不存在“先做依赖其后数据的上层页面”问题。

本轮反向审计发现并已修正五个设计缺口：

1. 原设计用 `publication_id` 直接承载每个历史日，无法兼容只有少数正式发布日的现状；现已引入不可变 `analysis_snapshot_id`。
2. 原设计没有把默认 A 股范围固化为合同；现已加入 `CN_A_CORE_V1` 和可审计排除原因。
3. 原设计没有区分板块自身涨幅与成员涨幅中位数；现已拆成两个字段和两个显示位置。
4. 原设计只描述了强势关联规则，没有专门结果表；现已增加 `stock_sector_associations_daily`，防止各页面各算一套。
5. 原采纳文档优先级仍残留每日导出、投资日历和AI复盘；现已按用户最终取舍移出近期实施范围。
