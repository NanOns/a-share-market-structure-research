# WP-A01 implementation and source-gate dispositions

Authority: `WP_A01_DM01_INCREMENTAL_BUILDERS_IMPLEMENTATION_TASK_R1_20261001.md`.

The nine exported functions implement target-session staging through static accepted domain runtimes. Four historical CLI-only kernels were extracted at build time with source ranges, original SHA bindings and explicit control-flow transformations. Historical CLI files and accepted arithmetic remain unchanged. The candidate path does not invoke historical CLI entrypoints.

Each component binds its frozen previous-session parent, source revision, calendar and identity publications, runtime bytes and independent postcheck. Period state combines frozen parent aggregates with the target daily bar; closed parent rows remain unchanged. The period digest protocol explicitly combines the frozen parent digest and target facts rather than pretending to resume an unavailable hash state. A revised source creates a new candidate from the same parent.

Only all nine components plus independent checks make the final staging marker visible. Failures retain partial evidence without exposing it through an accepted namespace or moving any head. Candidate receipts never grant production or Data Head promotion permission.

Persisted engineering evidence uses explicitly synthetic source and normalized parent inputs, including a binary TDX package. It exercises the actual adapters. These inputs, rows and candidate markers are not accepted market observations. The `--context` interface requires a complete frozen context with normalized parent component artifacts; it does not automatically manufacture one from an incomplete real source set. Real parent projections and a complete target-source context must be independently verified before any real candidate can be accepted.

The accepted calendar resolves the first required completed session after 2026-09-24 to 2026-09-28. Its frozen official TDX package and eligible GBBQ snapshot are verified. Exact dated BaoStock runtime acceptance and daily roster/status/ST/factor freezes are absent. The existing live-smoke source contract cannot retrospectively relabel a later observation. The real source gate therefore remains `BLOCKED_MISSING_INTERMEDIATE_SESSION`; no later date is selected and no real-market component/candidate is asserted.

Clean-checkout regression initially exposed a byte-binding defect: Git LF conversion of `config/v4_02_price_limit_rules_r3.json` produced SHA `0bd9d6f723170a55af6cf2d023c69abaddd958742f00d4f4137ee3ec33fadd02`, while the accepted R6 manifest binds SHA `68679333821c50cc8cbed5ff4cd001447cc6571d79b0d074a60b6bb81bdb01e0`. The accepted CRLF bytes are now stored with `-text`, with an explicit Git index renormalization; changing attributes alone left the old indexed LF bytes and caused a second failed run. JSON content, parameters and formulas are identical. The freeze step also checks phase-event, policy and rule bytes against the accepted manifest. Both failed regression receipts are retained separately.
