## 一、用户目标（最新权威）

**用户在 2026-10-08 明确要求：现有已实现 V4 算法及其研究成果全部按正常生产版本部署和展示；后续交易日数据积累、样本观察、算法评价与迭代在运营中持续进行，不得用“未授权/Shadow/长期验证未成熟”笼统否定既有成果。**

本总卡取代“继续只有7个已接受摘要区块”的前端范围，不追认或抹除旧独立验收证据。发布权限的历史旧规则需版本化迁移，而不是秘密篡改已经冻结的结论。整个系统**正式研究运营**不等同于**盈利能力统计证明**，也不等同于用户授权交易执行。

### 统一状态定义

| 维度 | 含义 | 用户应该看到什么 |
|---|---|---|
| `OPERATIONAL_PRODUCTION_ACTIVE` | 新版本工程可运行、真实输入、QA通过并准许正式研究消费 | 正常显示正式算法结果、版本、数据截止日 |
| `VALIDATION_ONGOING` | 生产算法正在继续收集真实Forward验证样本 | 生产结果正常可见；独立报告样本进度与不确定性 |
| `DATA_PENDING` | 下一交易日尚无完成/接收的输入 | 上一真实生产快照仍可见，更新日期不伪造 |
| `SOURCE_INCOMPLETE` | 某域实际数据源不完整 | 精确显示受影响字段/对象和原因；其他域继续运行 |
| `ENGINEERING_NOT_READY` | 对应算法确实尚不能安全运行 | 该域列明确修复任务，其他域正常生产 |
| `PENDING`/`RIGHT_CENSORED` | Forward outcome未到期/右删失 | 正常生命周期，不冒充完成结算 |

**旧 `production_permission[*] = false` 只说明旧合同的历史特定证明未成立，不是全站 UI/已有算法一概禁止使用的事实。** 01 卡必须根据用户新的正式运营目标制定 successor 发布政策与工程准入，留存旧版本、审计结论和范围迁移；不允许把历史旧权限硬刷 TRUE，也不允许拿长期收益统计未成熟永久绑架研究产品。
