# V4 全功能正式生产前端建设｜总调度与合同修订 R1｜2026-10-08

## 一、用户目标（最新权威）

**用户在 2026-10-08 明确要求：现有已实现 V4 算法及其研究成果全部按正常生产版本部署和展示；后续交易日数据积累、样本观察、算法评价与迭代在运营中持续进行，不得用“未授权/Shadow/长期验证未成熟”笼统否定既有成果。**

本总卡取代“继续只有7个已接受摘要区块”的前端范围，不追认或抹除旧独立验收证据。发布权限的历史旧规则需版本化迁移，而不是秘密篡改已经冻结的结论。整个系统**正式研究运营**不等同于**盈利能力统计证明**，也不等同于用户授权交易执行。

### 统一状态定义

| 维度 | 含义 | 用户应该看到什么 |
|---|---|---|
| `OPERATIONAL_PRODUCTION_ACTIVE` | 新版本工程可运行、真实输入、QA通过并准许正式研究消费 | 正常显示正式算法结果、版本、数据截止日 |
| `VALIDATION_ONGOING` | 生产算法正在继续收集真实Forward验证样本 | 生产结果正常可见；独立报告样本进度与不确定性 |
| `DATA_PENDING` | 下一交易日尚无完成/接收的输入 | 上一真实生产快照仍可见，更新日期不伪造 |
| `SOURCE_INCOMPLETE` | 某域实际数据源不完整 | 精确显示受影响字段/对象和原因；其他域继续运行 |
| `ENGINEERING_NOT_READY` | 对应算法确实尚不能安全运行 | 该域列明确修复任务，其他域正常生产 |
| `PENDING`/`RIGHT_CENSORED` | Forward outcome未到期/右删失 | 正常生命周期，不冒充完成结算 |

**旧 `production_permission[*] = false` 只说明旧合同的历史特定证明未成立，不是全站 UI/已有算法一概禁止使用的事实。** 01 卡必须根据用户新的正式运营目标制定 successor 发布政策与工程准入，留存旧版本、审计结论和范围迁移；不允许把历史旧权限硬刷 TRUE，也不允许拿长期收益统计未成熟永久绑架研究产品。

### 并行边界

A 先执行 FP-01。B 可让 `02数据`、`03 API`、`04前端框架` 三工作区并行，先冻结共同的数据/字段/权限合同。C 中 `05/06/07/08/09/10/11` 可分工并行，但统一读 03 API、共享04组件、不能互相覆盖；D 将跨页比较接入；E 一次完整独立验收；F 再正式原子发布。

**不必等待新交易日或满20个交易日之后才推进 C/D/E/F。** 但如果某模块真实生产输入或工程测试失败，只阻止相关功能发布，不得伪造；其余模块继续开发与验收。最终 FULL_PRODUCT 仍要求合同约定的全部入口和可实施功能闭环，不能以“七摘要可用”宣布全交付。

## 五、最紧急的反旧设计禁令

- 不再以 `V4_ACCEPTED_RESEARCH_READONLY` 七摘要代表全功能产品交付。
- 不再把 `production_permission=false` 机械转译为整个模块不可显示；先分辨旧证据门和现有真实计算能力，再按 successor 制度部署正式运行。
- 不再把 `UNKNOWN` 当作“未有下一交易日”或“前端无页面”的万能占位符。
- 不再让首页以板块成员数、股票收盘价代替真正的板块/个股算法研究结果。
- 不再固定每区6条、没有分页、首页堆 digest、页面英语枚举占据重点。
- 不把工程测试 / fixture / PENDING / 未成熟Forward冒充真实收益证明。
- 不以恢复 V3 旧 DB 或假 Shadow 行情作为“修好生产页面”的捷径。
- 不重开已经完成的底层阶段大修，除非出现实证工程缺陷；全部差异应定点修复。

1. 每模块独立证据 `feature→producer→source→API→UI→test→screenshot`，并列“旧成果沿用/新适配/确实需补算”三类。
2. 真实 Edge 浏览器逐个打开六入口及详情；全量可搜索可分页；上下文冻结，中文和图表正常；检查1366/1920分辨率。
3. 抽样数值与真实产物相核对。发布日期、算法版本、股票身份、复权/成交量和历史时点解释一致。
4. 禁止 TDX 修改、伪造历史门通过/伪造数据、旧 accepted head 覆盖、隐性自动交易。
5. 发布性能、失败隔离、并发上下文与可回滚测试必须通过。完成时记录 PASS/FAIL/BLOCKED 以及剩余独立统计验证债务。
