## 四、发现的真实问题与严重度

### R43-R2-AUTH-001｜直接用户授权的原始证明不足｜P0 审计债

新 `src/workbench_analysis/r43_release_control.py` 将授权验证为 `request_origin='DIRECT_HUMAN_USER_MESSAGE'`、固定 `request_text`、检查一份开发方创建的 MD SHA。MD 中引文为“**不需要等待什么批准生产准入 ,我现在要求你 进行生产数据切换**”。这可验证所保存的文字字节稳定，却**不等于验证文字确实出自有权限的用户**。用户可能在 Codex 对话另行发送了此指令，当前外审没有那段原始对话，故结论只能是来源 NOT_VERIFIABLE。必须关联原消息的时间/会话定位或原始用户提供的可核凭证，并独立复核。不能以本审计意见要求无证立即回滚正常使用中的合法事后运营数据，但以后不允许简单将“执行代理自建文本＋哈希”作为通用任意发布权限。

### R43-R2-CTRL-001｜`/api/operations/status` 顶层混合两套 Head｜P1 产品正确性

实际返回：
- `accepted_trade_date` / `trade_date` / `current_operational_trade_date` = **2026-10-08**，正确；
- `strict_pit_legacy_trade_date` = **2026-09-30**，正确；
- 但顶层 `last_accepted_trade_date=2026-09-30`、`data_head_digest=38e7c9...`（旧 Head）、`source_revision=7887e3...`（旧修订）、`stage=V4-15`、`namespace=V4_CURRENT_ACCEPTED`，`data_updated_at=2026-10-01...` 与新研究 `2026-10-09...` 不一致；
- `production_permission` 顶层五个旧能力域均为 false，实际 `production_accepted=true`。

这不是 10/08 API 数据失败，但会误导沿用旧字段的状态栏、前端与运维消费者。不要简单改成 true 或覆盖原 PIT：应版本化提供独立的 `operational_*` 和 `legacy_*` 结构，顶层冲突字段明确契约/废弃期，并加新旧 Head 一致性断言。

### R43-R2-UI-001｜HTTP 200 不等于完整页面 QA｜P1

R2 本机 HTTP 34 项均 200，重点域有候选数值。但 `/v4` 返回的是 983 字节 HTML SPA 壳，是否能正确显示全部六导航、详细数值、筛选和图形，需要 FP01–FP14 真浏览器逐页验证。原合同明确 chart/PIT replay/compare、Forward enrollment/statistics/plans/FEP/settlement、Market 部分子页尚未接正式 owner 并返回 `SOURCE_INCOMPLETE`。不应将壳页面 200 当成所有模块已完成。

### R43-R2-DATA-001｜数学外部覆盖与 10/09 日更｜P1/P2

Rotation 仍 `VALIDATION_ONGOING`。原四日正式研究数据可用并不证明 Rotation 数学全对。应后续独立构造竞争路径和递归状态机对照；并确认 10 月 9 日收盘之后的正式增量更新流程，避免本轮对 10/08 的切换成为日后“不再自动更新”的固定点。10/09 当日数据不在此次四日冻结验证范围内。
