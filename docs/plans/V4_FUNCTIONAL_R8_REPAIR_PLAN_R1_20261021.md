A4 实现细则：

### B｜研究流程与页面整合

目标：用户在六大研究入口之间切换、切日、打开详情和观察变化时，能够追到同一版本的有效证据。

1. 把 A 已通过的成果接入可复用的真实日更生产者与现有 BFF/Owner 路径。旧的截至 10-14 候选路径保持归档边界；新运行合同按合法 T0、交易日历、截止时间和依赖窗口计算，不通过简单删除日期保护获得通用能力。
2. 来源允许有不同合法时间：页面/API 必须同时表达行情 T0、成员快照时点、观察时间及发布/候选状态；不能把较早成员快照改写成当天，不能把“字段都写同一天”当来源一致。
3. Focus 区分“跟踪对象”“本次符合资格”“事件变化”“证据不足”。FIRST_CAPTURE_NOT_PROVEN 表达前瞻验证限制，不能在展示上暗示研究资格必然 FALSE；已有 D0/D2 资格与证据状态分别展示，是否调整既有正式门禁由对应合同裁定。
4. 对每个有结论的对象，提供关键数值、入选/排除原因、相对上一有效版本的变化、失效条件及源版本。对未知项说明受影响的结论，避免只追加 UNKNOWN 标签。
5. 总体、排除、缺输入、分页和展示条数分别对账。Focus 跟踪池、Radar 事件池、Priority 候选不能混作同一分母。
6. 一次真实浏览器核验六大入口，覆盖详情、筛选、切日、日周月/QFQ 图、缓存更新、错误与重试；使用不同股票/板块及有公司行动、新股、缺数据的代表对象。截图只保留异常和必要证明，不逐按钮制作报告。

验收：有一条真实“市场→板块→个股→资格/失效→Focus→Forward 状态”的可追溯路径；各入口同 token/T0 或明确合法历史版本；无跨日旧缓存混入、伪造首捕或统计误读。尚无真实 Forward 到期结果时展示等待及期限，不把等待当算法缺陷，也不声明成熟验证通过。
